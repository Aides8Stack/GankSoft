## 严格的完成认定
- `IMPLEMENTED`：源代码/操作已修改，未验证。
- `PASS_LOCAL`：本地专项通过，但仅可用于该平台/入口。
- `PENDING_WINDOWS_UI`：等待正式 Windows 真实截图。
- `PASS_WINDOWS_UI`：同一 SHA 的生产 EXE 截图/交互已核实。
- `UI_V37_DONE`：P0-P6 核心必验项全部 PASS，且发布安全条件满足。

## 中断救援
断连/额度 < 10%（如果 Work 可以读取额度）/无法再取得所需工具时，停止新增开发、保留未提交变更，优先正常提交和推送有效代码与非敏感测试摘要到原工作分支；记录 `RECOVERY-NEXT.md`：HEAD、WIP、下一入口、变更文件、具体尚缺的截图/测试、CI URL。无法推送只读保存完整 git bundle 或差异包，并核对可恢复性；不要为写日志上传用户学习数据库或敏感信息。不等待 CI 无限重试。

## 所有者审批边界
- 本轮用户授权**在已有项目中进行完整 UI 改进并形成可审核 PR**；不表示同意自动合并 develop 或发布 Release。
- 复用原 feature 分支需先核实远端和安全 fast-forward；新 PR 用现有流程，无需对旧 PR #13/#14 作破坏性操作。
- 版本不能沿用已合并 rc.2；选择下一可用合法 semver（例如 rc.3，须核实 Tag/Release 是否被占用），不得绕过 trusted `version.mjs`。
- 如果涉及 `tools/`、`package*.json` 等控制文件，由所有者对**最终 SHA**执行 `pr-trust`；不要自行冒名审批。
