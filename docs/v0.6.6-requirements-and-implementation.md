# GankSoft v0.6.6 RC：六项问题优化方案与实现

基线v0.6.5 RC；日期2026-10-17。根据用户《问题.md》q1—q6及7张截图增量修改，无重写项目。Windows10/11实机验收未完成，保持RC。

## 需求与最终行为

| 问题 | 已实现方案 | 验收 |
|---|---|---|
| q1 页面管理出现在其他功能栏 | 复盘页签、Home和管理入口仅在当前卡片集“所有卡片”及其复盘页显示；本集仅显示本集会话。其他功能页恢复普通面包屑 | 汇总、知识图谱、分析、导入、设置、详情、总览无页签；返回所有卡片可见 |
| q2 分析隔离与模块化 | 独立后端只读分析模块，API必填deckId；题目、记录、错因、知识点/关联均从本集读取；前端按集创建实例并丢弃过期响应 | 两个集使用不同题目/知识点和错误记录，分别只显示本集；总览仍跨集汇总 |
| q2 多余UI | 去掉“各卡片集学习情况”、知识点表的“模块”列，以及错题分析中的无关记忆卡面板 | 单集页面不再重复全局汇总或重复集名列 |
| q3 弹层自动收起 | 外部pointerdown、Esc、导航、切页、失焦、主体滚动自动关闭；关闭页面操作也收起 | 内部点击不误关，外部/按键/切换后不残留 |
| q4 复盘→详情→返回 | 进入前记录来源页面、集、会话ID和滚动位置；返回时恢复指定会话 | 第二题结果步骤往返后仍为原页、原题、原步骤/进度；原稿和结果不丢，计时保持暂停 |
| q5 详情职责 | 改名“题目详情”，返回按钮为“返回上一个页面”；去掉详情中的新增、删除、选题入口和隐藏题目列表 | 从卡片列表、分析、复盘进入均返回来源；列表筛选保留。单卡编辑、复盘设置、基础内容和历史仍可查看 |
| q6 基础内容唯一、复盘统一 | 卡片只展示一套当前基础内容；移除内容版本选择、版本标签和每条记录复制的题目/选项/解析；全部复盘统一统计和连线 | 编辑基础内容后仍仅一张卡；旧新记录都可见，自评/时间/思路和反思各自保留 |

## 模块和API

- `electron/modules/analytics/deck.ts`：卡片集分析只读模块，规则版本`deck-insights-v1`。不依赖Vue、不修改题目/复盘/排期；后续规则更新集中在此模块。
- `analytics.deck({deckId,range})`：range为7/30/all，返回本集统计、错因、反复出错题目及知识点覆盖。所有数据源均按当前存活卡片集限定，关联同时校验题目与知识点的所属集。
- `electron/modules/analytics/timeline.ts`及`analytics.card.timeline({kind,cardId})`：单卡统一时间线。按卡片ID读取全部复盘记录，统一计算平均值、最近有效自评变化和独立复盘日证据；不按内容修订拆分。
- 契约在`shared/protocol/registry.ts`，DTO在`shared/review-analytics.ts`，生成Codec与协议导出同步；`src/services.ts`为前端适配，统一桥及协议2.0不变，公开方法由56增至58。
- `Insights.vue`只负责加载/展示，显式接收deckId，使用请求序号和卸载失效防止响应串集。总览继续使用既有跨集汇总，不复用单集分析页。
- `App.vue`负责页面栏作用域、弹层生命周期、详情来源恢复；`QuestionLibrary.vue`保留组件实现但界面职责收敛为题目详情。

规则：有效复盘正确率基于本集有效记录；反复出错为所选时间范围内最近三次有效作答至少两错；错因在同次复盘中去重；知识点错误只统计实际标记且属于本集的知识点。答对但不稳定基于当次方法成功判定，包含未更新排期的猜测/提示等观察记录，避免仅用调度等级2误判。

## 唯一基础内容与历史保护

基础表仍为每张卡片一个ID、一行当前属性；编辑更新同一行，不创建可切换的内容分支。每次作答保留独立选择、思路、自评、用时、反思及当次判定，统一归属该卡片。修改当前正确答案不会追改历史正误。

内部修订号、冻结原稿校验及既有不可变审计快照保留，用于并发冲突、提交归属和备份完整性；不作为用户可选择的“卡片内容版本”，不在详情/复盘统计重复呈现基础题目。旧的审计统计接口保留给底层与已有回归，应用界面改用统一时间线API。数据库schema601、数据目录v060/data保持不变，无破坏性数据清理。
