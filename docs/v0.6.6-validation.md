# GankSoft v0.6.6 RC：优化方案与验证报告

日期：2026-10-17；基线：v0.6.5 RC；交付：v0.6.6 RC。依据用户《问题.md》q1—q6及7张截图完成增量优化。Windows10/11实机验收仍未执行。

## 六项问题与已实现行为

| 问题 | 已实现 |
|---|---|
| q1 页面管理越界 | Home、复盘页签、管理入口仅在“所有卡片”及其复盘页显示，而且只列当前卡片集会话。汇总、导图、分析、导入、调度设置、详情和全局页恢复普通标题栏。 |
| q2 分析隔离 | 拆出独立后端只读分析模块；API必须指定卡片集，题目、复盘、错因、知识点和关联均按集过滤。去掉各集汇总及知识点表“模块”列。学习总览继续跨集汇总。 |
| q3 弹层收起 | 点击外部、Esc、导航、失焦和主区域滚动自动关闭；页面关闭动作也收起管理弹层。修复了窗口blur目标不是DOM节点时的判断错误。 |
| q4 返回复盘 | 进入详情前保存来源页、卡片集、会话及滚动位置；返回原会话的当前题目、步骤、进度、原稿和结果，计时仍暂停。 |
| q5 题目详情职责 | “题目项目页”改名“题目详情”；返回进入前页面，不再固定返回所有卡片；移除详情中的录入、删除及选题管理入口。基础内容、编辑、单卡设置与逐次历史仍可查看。 |
| q6 唯一基础内容 | 移除内容版本选择、版本标签和每条记录重复的题目/选项/解析。每张卡片展示唯一当前基础内容；全部复盘统一统计、连线并保留每次答案、自评、用时、思路和反思。 |

基础属性编辑更新同一张卡片，不生成可选择的内容分支；历史正误按当次判定保留，不因修改当前正确答案而重算。内部修订校验及既有不可变审计快照继续保护并发、原稿冻结、提交归属及备份完整性，不作为用户内容版本呈现。未删除卡片、复盘历史、排期或用户数据。

## 独立模块与API

- `electron/modules/analytics/deck.ts`：本集错题分析，规则标识deck-insights-v1；不依赖前端、不写入业务数据。
- `analytics.deck({deckId,range})`：7天/30天/全部；返回当前集统计、去重错因、反复出错题目、知识点覆盖。
- `electron/modules/analytics/timeline.ts`及`analytics.card.timeline({kind,cardId})`：以卡片ID汇集全部复盘，统一计算统计、自评变化、跨日独立证据；保留原记录内容。
- `Insights.vue`显式接收deckId，切集新建实例并丢弃过期请求；`src/services.ts`提供适配。契约/DTO/Codec/导出已同步，协议2.0及统一桥不变，公开方法58个。
- 旧审计统计接口仍保留供底层校验，实际应用界面改用统一时间线。数据库保持601、v060/data不变；从0.6.5升级无需新增数据库迁移，已有600→601保留原数据的升级仍可用。

完整设计及入口见源码 `docs/v0.6.6-requirements-and-implementation.md`。

## 用户验收步骤

完整解压Windows ZIP，运行GankSoft.exe：

1. 打开一个复盘页，再依次进入汇总、导图、分析、导入、调度设置，页签/管理入口均应消失；返回所有卡片后恢复，其他集会话不混入。
2. 两个集分别建立独有题目/知识点及复盘记录；分析只能显示本集。总览应能看到全部集的汇总。
3. 打开页面管理，点击外部、按Esc、滚动或切页，应自动收起且不在下个页面残留。
4. 在复盘第2题完成保存后打开题目详情，再点返回：应恢复原页、第2题、已保存结果、原稿和进度，计时暂停等待手动恢复。从分析/卡片列表进入详情也应返回来源，列表筛选保留。
5. 详情应无“录入错题”“删除”入口；编辑基础内容后仍仅一张卡片。复盘统计无内容版本选择，全部记录都在，自评/时间走势不中途按版本分组。

开发验收：npm run check、npm run test:package、npm run smoke:v066。真实Win10/Win11各执行tools/validation/windows-test.ps1并完成人工矩阵与上述步骤，双系统同ZIP/EXE哈希且真实签核通过后再release:verify。没有Windows环境不生成通过记录。
