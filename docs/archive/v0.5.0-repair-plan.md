# GankSoft v0.5.0 修复方案

基线：v0.4.11、审计 A01—A15。保持模块化单体与复盘工作流事务；不访问用户数据库。

## A01 P1 同一作答编号能切换到另一张题，旧思路被记到新题

方案：在会话模块建立不可变 entry 锚点（cardId、contentVersion、answer、thought），每次保存和提交都校验；下一题由后端合法转换创建新 entry。保持 workflow 的单事务边界。

验收：将 D06 改为断言第三步拒绝；a、b 都无新增复盘，队列与调度不变。补充重排 ids、改 index、复用 entryId 的变体。

## A02 P1 省略旧格式字段即可绕过原稿冻结和会话并发保护

方案：兼容迁移仅允许读取／一次性升级旧数据；写命令必须有明确 schema 和 expected_revision。对已有现代会话拒绝降级，状态规则与输入格式解耦。

验收：D05 改为拒绝覆盖；两个旧 revision 的写入只允许一个成功；旧数据库草稿升级后仍能保留原文并显式重新作答。

## A03 P1 卡片移动后，原卡片集的旧会话仍可提交有效复盘

方案：提交时验证 card.module===deck_id、deck live、队列锚点有效；移动模块调用会话失效接口保留旧草稿。不要由 UI 自行修正数据库。

验收：D11 改为拒绝；B 不生成新排期事件，A 不推进；刷新后可查看移动前原稿并选择合法后续动作。

## A04 P1 跨集知识点关联未受约束，移动后可污染原集漏洞证据

方案：知识模块提供所属集校验；卡片移动服务显式处理当前关联（默认解绑或要求目标映射），保留历史知识快照。若产品要共享知识，必须改为显式共享实体及展示，而非偶然跨集。

验收：拒绝 D03；D02 移动后无隐式外集关联，A 的新证据不增加；历史详情仍显示当时知识点名称；导出／删除原集后 B 数据完整。

## A05 P1 缺失和异常类型的用时被转换成真实数值，污染统计

方案：使用运行时数值校验，新增可空用时及记录来源字段；UI／DTO 保留 null。旧版 0 秒不能盲目改为 null，需按可得来源标记未知。

验收：D01 改为缺失/null→null，0→0，空串/布尔/对象/非有限/负数/超限→拒绝；混合样本的均值和分母与 SQL 一致。

## A06 P1 删除或移动当前卡片后，“跳过并继续”无效

方案：按钮显式调用 next(true)；由会话后端确认缺失／移动并推进，保留草稿审计。验证最后一张、连续多张失效和完成状态。

验收：将 ui-audit 的 D09 改为 index 递增并出现下一题；不得产生被跳过题的复盘或调度记录。

## A07 P2 密集折线点的命中区域重叠，点击可选错记录

方案：图表容器按最近坐标选择唯一 id，或提供横向滚动/缩放与稳定的记录列表定位；不要仅缩小命中区导致更难点。保留键盘选择。

验收：60、120 条同分／同用时点，逐个中心点击与键盘 Enter/Space 均对应唯一 SQL 记录；选中样式和详情一致。

## A08 P2 默认统计仅显示当前内容版本，与本轮“默认覆盖每次保存”要求不符

方案：默认全部记录，按版本分段绘图且不跨版本连线，或在默认全历史视图提供版本分区；保留单版本过滤。需更新现有把默认空记录视为通过的旧测试。

验收：D07 改为默认可定位旧记录；混合版本不连线，不计算跨版自评变化，并显示版本边界。

## A09 P2 备份恢复校验不检查学习会话，非法会话可通过暂存验证

方案：提取只读业务完整性校验器，检查会话版本、JSON、队列身份、revision、待确认提交和回执关系；暂存通过后才替换。不可直接调用有写入副作用的 saveSession。

验收：D08 改为明确失败，原库逐表和附件哈希不变；损坏其他 JSON 字段也有可定位错误，不把正常旧草稿误删。

## A10 P2 复用筛选器 ID 可改写另一卡片集的筛选内容

方案：拆为筛选服务；更新要求 id+deck_id+revision，校验所属集和筛选 DTO；新建与更新语义明确。

验收：D12 改为拒绝，A 内容不变；同集合法编辑成功；错集删除也应验证；普通 UI UUID 路径继续通过。

## A11 P2 仅含 PNG 文件头的损坏图片也能导入成功

方案：图片基础设施提供统一验证（解码、尺寸、大小、MIME），手动和导入复用；写文件和入库保持可补偿的事务边界。

验收：D13 改为字段级错误且不落盘；截断 JPEG/WebP、MIME 伪装、有效小图分别拒绝/接受；错误提示可重试。

## A12 P2 千卡万次历史的列表加载出现可测的数秒等待

方案：先建立可重复性能预算与 profile，再用分页/虚拟列表、按卡预聚合索引和精简 DTO；保存后避免每次传全历史。保持统计只读和业务事务独立。

验收：同环境至少 5 次前后对比，记录硬件/数据/冷暖态/中位与尾值；分页前后计数、筛选、选择及历史详情完全一致；Windows 另实测，不能复用本数字。

## A13 P3 规则调度旧算法仍以可调用导出保留，与 FSRS 活跃实现并存

方案：拆出纯日期／评分工具；旧算法移入明确 legacy 命名空间并文档化用途，或确认无兼容需求后删除。无需微服务或事件总线。

验收：静态依赖检查确认活跃排期只走统一 FSRS 入口；历史记录 algorithm 文本不被改写，旧迁移测试继续通过。

## A14 P3 错误协议只有通用拒绝码，缺少字段与冲突类别

方案：建立小型领域错误类型及映射层，保留 call envelope；统一字段级错误、内容/会话冲突码、提交结果不确定标记。不要让调度模块依赖界面文案。

验收：分别注入校验、revision 冲突、内容冲突、未知传输失败，断言稳定 code 和字段定位，输入保留，重试行为正确。

## A15 P3 随包界面回归脚本仍依赖已删除功能和旧版本常量

方案：更新测试入口和场景清单，标记过时脚本；版本检查读取被测包。保留导入集隔离、预览重置、重复提交和即时学习的业务断言。

验收：原需求场景在新版脚本通过；移除对已删除按钮和固定旧版本的依赖；用删除有效 UI/破坏集隔离的负例确认测试仍能失败。

## 数据迁移策略

schema 8：新增可空 elapsed_value 和 elapsed_source，原 elapsed_seconds 保留兼容。旧数字原样保存并标记 legacy_unknown，不猜测旧 0 秒含义。新增记录缺失用时为 null；统计通过明确读模型返回。新增筛选 revision 及历史查询索引。迁移在事务内执行。

## 产品边界

暂停是否禁止手动复盘、后台计时是否继续仍为产品歧义，本版不改变。移动默认解绑当前跨集知识关联，历史快照保留。全部版本图表在版本变化处断线。
