## 0. 一句话目标与边界

系统回答三个不同问题：**这道题是否真正会做？这一知识点是否已能迁移到其他题？今天应该先做什么？**

- 题目级 `QuestionDiagnosis`：独立解题表现、方法完整性、错因、解题效率、近期变化、证据量。
- 知识点级 `KnowledgeDiagnosis`：不同题目/跨日期的独立表现、明确错误归因、覆盖率、题型/变式覆盖、长期趋势、证据可信度。
- FSRS：继续决定每张已调度卡的记忆状态与到期日；**知识点的风险绝不反向写入 FSRS 参数或到期日**。
- 联合队列 `ReviewQueue`：在到期合规前提下，综合卡片风险、知识点薄弱程度、逾期紧迫度、知识覆盖缺口、反复错因进行可解释选择；专项练习与 FSRS 正常复习分账。

现有栈与职责保持：Vue3/TS + Electron、`ts-fsrs`、类型化 gateway、事务/回执、每卡个性化调度、卡片集隔离、两类记忆卡与错题卡隔离。不得重写整项目、清空学习数据库或覆盖未提交的代码。

## 2. 新的证据哲学：不固定次数、不固定观察窗口

### 2.1 使用全部“适用的”历史

当前题目内容版本及相应知识点关系版本内的所有可用事件，都可以参与诊断；早期证据保留但逐渐减权。**不以三次、六次、30 天或 90 天截断数据**。用户在界面选择 7/30/90/自定义区间只改变可视化历史和显式的区间统计，不应悄悄影响“当前掌握诊断”或 FSRS 排期。

不可将旧内容版本失败自动迁移成新版题目缺陷；旧版本继续显示在历史时间线中。对知识点新建立的关联，不可将旧答对记录反向解释成这个新知识点的正面证据。

### 2.2 证据分类

- `strong_positive`：独立作答正确、未看提示/答案、方法或关键步骤可解释；用时可信。题目和关联知识点可获正面证据。
- `strong_negative_item`：独立作答错误；至少对题目提供强负面证据。
- `strong_negative_knowledge`：失败且明确选中了具体 `error_knowledge_ids`；**只对被明确指出的知识点**提供负面证据。
- `ambiguous`：猜测正确、凭记忆背答案、看提示、思路不完整、未给知识点归因等；用于诊断/提示，不构成高置信知识点掌握证据。
- `practice_observation`：专项/随机/手动提前练习的数据保留；默认不改正常 FSRS 日程，也不等同于一次独立新题验证。

所有事件保留 `attempt_id`、题目/内容版本、知识点快照版本、时区、时间、作答模式、是否有效、选择、自评、用时、错误分类、回执与数据来源。重复 request_id 只能入账一次。

### 2.3 防止“刷熟一道题就掌握知识点”

- 每个 **题目 × 学习自然日**，仅以第一次真正独立、无提示的作答作为主要“熟练证明”；当天后续重做属于纠偏/训练过程，展示但不重复累加独立掌握次数。
- 不同题目、不同自然日提供较强的独立覆盖证据；同一题跨日重新成功仍可体现保持情况，但其对整个知识点的累计贡献受上限/递减权重约束。
- 练习题如内容高度重复、同模板仅替换数字，可选记录 `variant_group_id`，同一组不必被当成多个完全独立知识覆盖点（**先设计扩展位，不要求 v1 自动识别模板**）。
- 不以做对总次数作为知识点掌握的充分条件；显示独立题目数、跨日天数、有效证据量与覆盖率。

## 3. 可解释的基线自适应评分（v2 初始工程参数，并非已校准学习概率）

建议先实现纯函数、确定性、可回放的 `evidence-model-v2.0`，保留数据以便后续标定。不要把数值渲染成“掌握概率 83.7%”。

### 3.1 时间权重，无窗口硬截断

对于相隔 `ageDays` 天的适用事件，建议初始：

```text
timeWeight = 2 ^ (-max(0, ageDays) / halfLifeDays)
initial halfLifeDays = 60   // 可通过离线对比调参；非公认最优数
```

例如距今 0/60/120 天的基础权重分别为 1 / 0.5 / 0.25。正面证据与负面证据均衰减；时间较久不是“重新判错”，只会提高待验证/证据过时信号。

时间以学习时区自然日和权威时钟计算，防止 DST/跨午夜、未来时间戳、系统时钟回退使权重异常。历史记录永远不删除。

### 3.2 同题重复修正

按题目 ID、内容版本、学习自然日去重主要独立证据。同一题跨不同日的第 `n` 次独立暴露，可先采用递减贡献 `repeatFactor = 1 / sqrt(n)`；对于知识点级分析，每道题在一个评分快照内的**总有效贡献上限 2.0**。这样连续刷同一题不能压倒其他独立题目，但近期单题变化仍可体现在题目诊断里。参数需有 `ruleVersion` 和可测的贡献解释。总限制在时间衰减之后应用，保留时序关系。

一题关联多个知识点：一次正面事件的总证据额度最多为 1，默认在当时明确关联的 N 个知识点间分配为 1/N；若错误只归因于其中 M 个，负面额度最多为 1，并仅分配给这 M 个。多个错因标签不重复计入知识点负面总量。父节点汇总需基于唯一事件去重，不能与子节点再加一次。

### 3.3 平滑风险指标

令 `B` 为加权负面证据、`G` 为加权强正面证据。可测试的初始平滑指标：

```text
errorEvidenceIndex = (1.5 + B) / (3 + B + G)  // 0..1; 高 = 最近存在较多失败证据
```

该式是有先验平滑的**证据指标**，不是某题或某知识点的真实错误概率；尤其没有证据时得到 0.5，界面必须呈现“证据不足 / 无法定级”，而不是“风险 50 分”。

题目风险可以再考虑独立解题失败趋势、方法未掌握、超时比例（只有存在目标时才算）、迟近的重复错误；FSRS 到期程度单独显示，不当作个人能力差的证据。

知识点风险按有可信快照的归因事件独立聚合，另给出 `unattributedFailureCount`、`unknownLinkHistoryCount`，不能把无法归因的失败编造成各知识点错误。

### 3.4 证据可信度随数据自然增长

不使用“至少 3 次”“必须 4 道题”等硬性掌握门槛，而按以下维度形成连续 `evidenceConfidence`：

1. 时间加权后的独立证据量（`effectiveEvidenceN`）。
2. 不同题目数、不同自然日数。
3. 已验证的知识点关联/错因归因比例。
4. 关联题总体覆盖率，是否有不同变式/题型覆盖。
5. 老证据占比与距最后独立验证天数（`staleEvidence`）。

推荐使用增长渐缓的贡献函数，例如 `1 - exp(-x/k)`，合成后的分数上限为 1、单调、可解释。不可显示未经标定的小数概率。每个维度在 UI 中要可展开查看。

**状态输出与风险、可信度分离**：`unseen` 未接触，`insufficient` 证据不足，`suspected_weak` 疑似薄弱，`weak` 薄弱，`unstable` 波动，`improving` 改善中，`stable` 相对稳定，`stale` 缺少近期验证。`coverage_gap` 作为独立布尔/分级标记。不因为证据老化就直接从稳定变成薄弱；优先变为 `stale` 待验证。

判定状态需要高低阈值与**滞后保护 (hysteresis)**，防止一次对错就让“薄弱 ↔ 稳定”频繁跳变。阈值应在配置常量中集中管理并有模型版本，允许经过回放测试后调整；不要把某个固定复习次数写成业务事实。

### 3.5 具体示例

- 同一道 Q 做对十次，多集中在一天：Q 的近期表现可以改善，但对应 K 仍提示“缺乏跨题验证”。
- K 的 Q1 过去十次错、最近 Q2/Q3/Q4 跨日独立做对：保留旧错因历史；时间衰减后，K 可以从薄弱→改善中→稳定，不被旧错误终身锁死。
- K 曾长期稳定但半年未接触：显示“历史稳定、当前待验证”，不可自动判为现在能力差。
- Q1 含 K1/K2，错在 K2：Q1 题目风险上升，K2 收到负面证据，K1 不能被错判为薄弱。
- Q1 因换题干更换内容版本：旧内容相关题目诊断不再污染当前版本，新版本归为待验证；旧学习史仍在。

## 4. 独立知识点、题型与子树聚合

- 保留 `knowledge_id` 与卡片集作用域，知识层级、题型分类、错因标签是不同维度；不要把树上父知识点误当成一道题的额外学习事件。
- 叶子直接统计；父节点将其子树内唯一事件、唯一问题去重汇总，允许一个问题关联多个子节点但在父汇总最多计一次。若同时直连父与子，说明解释关系但证据去重。
- 题型可以作为独立 facet 诊断：例如资料分析/增长率/时间口径，分别追踪方法错误与时间问题。没有可靠独立题型字段时，先使用已明确命名的层级标签显示，勿推测/自动标注旧数据。
- 具体知识点错因与整体正确率可不一致：一道题正确但方法错误属于方法警告，不应等同于全错；错题未选知识点归因属于“无法确定具体薄弱知识点”。
- 同一事件对不同关联点共享有限证据配额，避免多知识点题造成虚高；标签重关联时保留旧快照而不重算旧事件的语义。
- 政治理论/常识的记忆卡继续按 FSRS；不要把纯记忆卡的一次记住等价于多步骤错题的独立解题能力。可以共享视图组件，但证据通道分离。

## 5. 新的联合复习队列

**不要把诊断公式等同于排期公式。** 先通过现有 FSRS/计划状态判定合法到期集合，再在集合内排序，最后按剩余练习预算选择专项任务。

候选池：

- `scheduled_due` 到期有效复习，优先保证合法到期题被服务；
- `same_day_relearn` 同日重学，和“当日新进入的不同卡片数”分别计预算；
- `repeated_error_intervention` 重复错因专项（非到期默认练习）；
- `weak_knowledge_practice` 薄弱知识点跨题训练（非到期默认练习）；
- `coverage_verification` 未覆盖的变式、跨日迁移验证（非到期默认练习）；
- `manual_random` 用户自由与可复现随机选题。

每张题在同一个会话队列中唯一一次，题目关联多个薄弱知识点时按**边际知识覆盖收益**计算推荐价值，不重复占用预算。已学会的 Q1 可以保持自己的 FSRS 排期，同时 K 薄弱时优先从 Q2/Q3/新变式选训练题。

### 5.1 分层保底、风险排序、覆盖多样性

1. 先保证强逾期/普通到期有合理份额：初始可实验为“当日到期名额中至少 30% 给严重逾期题”（不足则由普通到期补足）；严重逾期依据相对原排期间隔和实际逾期时长综合定级，而非孤立一个固定天数。
2. 剩余到期名额，依据 `questionRisk`、`knowledgeRisk * confidence`、`overdueUrgency`、`knowledgeCoverageNovelty` 归一化联合排序，初始可为 0.40/0.25/0.25/0.10，但**须可配置/可回放，不宣称最优参数**。
3. 加入同一知识点连续出现的上限、变式覆盖度、最近疲劳/同日重复去重、低覆盖点适度探索，防止推荐列表单一。
4. 稳定排序：分组键、风险、原到期时刻、题目 ID；随机专项必须显式种子、且可重放。
5. 默认不抢占合法到期任务预算去做非到期专项；用户可手动选择专题，清楚标注与 FSRS 的区别。

### 5.2 预算与会话

- 日额度统计**独立到期题 ID 数**（去重），不是当日有效 attempts 数；同日重学单列。
- 专项题、跨题验证单列预算与时长，允许用户定制。
- 同一 `request_id` 幂等且不重复占用预算；会话恢复保留快照与规则版本；跨设备/时区边界使用明确学习时区自然日。
- 手动延期/计划状态与 FSRS 计算路径只能由统一 due eligibility service 输出，不允许前后端各用不同到期判断。

## 6. 数据结构、兼容与迁移

优先延用现有 `attempts`、`attempt_faults`、`question_knowledge`、`scheduling`、`plans`。仅增量增加存储“作答当时关联”的证据表/快照；不要迁移或清空现有 `v060/data`：

```sql
CREATE TABLE attempt_knowledge_evidence (
  attempt_id TEXT NOT NULL,
  question_id TEXT NOT NULL,
  content_version INTEGER NOT NULL,
  knowledge_link_revision INTEGER NOT NULL,
  knowledge_id TEXT NOT NULL,
  verdict TEXT NOT NULL, -- positive_independent | negative_attributed | ambiguous
  raw_credit REAL NOT NULL CHECK (raw_credit >= 0 AND raw_credit <= 1),
  source_kind TEXT NOT NULL, -- explicit | snapshot | legacy_known | legacy_unknown
  created_at TEXT NOT NULL,
  PRIMARY KEY(attempt_id, knowledge_id)
);
```

示意字段应适配现有 SQLite 命名、索引、约束和迁移模式；**不是要求逐字复制。** 同一题知识点关联可以单独提升 `knowledge_link_revision`，不必强制重置 FSRS。新证据与 `attempt` / `receipt` 必须在同一事务里原子提交。

老数据：显式标注的 `attempt_faults` 可作为“已明确的知识点错误”候选来源；未保存当时完整关联快照的旧“正确”事件不许当成新关联知识点的强正面证据。无法确定的 legacy 仅提供总历史统计/低可信解释。知识点合并删除保留映射及审计日志，不静默篡改旧证据。完整备份恢复必须包括新增表并对旧备份保持兼容；内容交换包不能冒充完整学习备份。

## 7. 计算接口与性能

纯计算函数（建议模块职责，实际文件路径遵循项目惯例）：

```ts
analyzeQuestionEvidence(events, now, rule): QuestionDiagnosis
analyzeKnowledgeEvidence(snapshotEvents, taxonomy, now, rule): KnowledgeDiagnosis[]
composeReviewQueue(dueState, questionDiagnosis, knowledgeDiagnosis, budget, filters, seed): ReviewQueuePreview
```

统一返回 `ruleVersion = 'adaptive-review-v2.0'`、`evidenceVersion`、`calculatedAt`、`studyTimezone`、`dataRevision`、`riskBand`、`confidenceBand`、`sampleCounts`、`reasonCodes`、`appliedCaps`、`exclusionCounts`、`status`。解释示例：“这道题在两个不同日期独立失败；关联知识点时间口径有多道题的明确错误；目前逾期 4 天”。不能展示无依据的绝对能力百分比。

高性能：SQL 聚合 / 按卡片集分页、相关证据最小读取、可复用且按 `deckId + dataRevision + ruleVersion + studyTimezone` 缓存；修改记录、卡片、知识关联、标签、删除恢复、导入/还原、学习时区或策略时失效。请求并发回包需防止迟到覆盖；只读预览不得改变数据库或调度。

## 8. 复习工作台 UI（当前生效入口，不要改废弃页）

1. **今日复习摘要**：到期数、严重逾期数、最近失败警告、薄弱/待验证知识点数，均展示口径。
2. **左侧知识树**：显示 `相对稳定 / 改善中 / 薄弱 / 证据不足 / 证据过时`，附独立题数、覆盖率和错因；树可筛选子树。
3. **中央推荐队列**：题型、题目难点、知识点、到期时刻、推荐理由、训练模式；允许排序并提供“为何推荐”弹窗。
4. **右侧诊断**：题目与知识点并排；展示完整历史趋势、独立作答趋势、同题次数与跨题证据的区别。
5. **模式入口**：正常到期、错因纠偏、薄弱知识点、跨题变式验证、自选/随机。
6. **筛选**：时间段、知识点子树、题型、错因、是否到期、是否曾独立验证、练习时长、数量、随机种子。时间范围仅影响用户明确选择的“历史统计/基于该范围选题”，绝不隐式篡改当前诊断/FSRS 状态。
7. **完成反馈**：即时展示单题结果和知识点证据的变化及理由，练习题标注“未改变原排期”，避免误导用户。

## 9. 分阶段交付

- **P0 核查**：核对当前真实源码、入口与未提交变更，冻结基线；在合成数据上添加旧排序失真/版本混入/延期差异/每日重复计数的失败回归用例。
- **P1 正确性**：处理内容版本和知识关联历史边界、手动延期唯一到期口径、每日独立题去重；不得覆盖用户数据。
- **P2 自适应诊断**：纯函数题目证据模型、知识点证据模型、时间衰减、同日同题独立限制、跨题/多日可信度、增量证据快照及原子写入，保留历史回放。
- **P3 联合队列**：服务端权威预览、严重逾期保底、知识点多样性和跨题变式、确定性/随机复现、会话恢复/预算隔离。
- **P4 UI**：现行学习页面改造，概览/知识树/诊断/推荐理由/筛选/专项/随机；空数据、证据不足、老记录欠缺快照均有明确 UI。
- **P5 质量交付**：单元、集成、协议、性能、合成库备份恢复和构建；静态 Linux 不等于真实 Windows。真实 Win10/Win11 未执行一律标 `not_run`；源码/运行包按实际能力交付，记录精确 SHA256。

## 10. 必须执行的验收场景（不只是测试名）

A. 20 次旧失败 + 最近四次来自不同题目的跨日独立成功：知识点风险应有改善趋势，不因旧错终身标为弱。
B. 同一题同日做对 10 次、不同题未练：单题可改善，但知识点显示覆盖不足，不能高置信稳定。
C. 不同 5 道题跨 4 天独立答对，且变式覆盖良好：即使总次数少，也应比 B 的知识点证据更可信；具体状态由模型计算而非硬编码 5。
D. 很久以前稳定、最近无验证：优先 `stale`，不能仅因时间流逝自动转为 `weak`。
E. Q1 关联 K1/K2，失败明确归因 K2：仅 K2 负面，Q1 负面，K1 不受罚；未归因时不得推断所有 K 失败。
F. Q1 今天失败，今日稍后看答案重做正确：保留纠偏过程，但不能以第二次成功冲销第一次独立失败的主证据。
G. Q1 内容改版：旧错误存档，新题诊断重新判为证据不足；未改题干仅调整知识关联：不得凭旧答对授予新增知识点正面证据。
H. 一题挂 K1/K2 与父 K0，1 次事件贡献总额不超过 1；父节点去重，不重复累计。
I. 题目 FSRS 到期与知识点弱化彼此独立；非到期专项不能偷偷修改 FSRS 到期或排期日志。
J. 到期严重逾期题不会被近期连续失败题无限挤出；每日额度数独立题数、幂等回执不重复记账。
K. 跨卡片集/记忆与错题、学习时区、跨午夜、非法时间、未来时间、备份与旧备份恢复、知识点删除/合并/孤儿关联，均有明确边界与测试。
L. 同一批事件使用同样 `now`、配置、模型版本得相同结果；窗口筛选改变趋势图但不改变当前诊断及 FSRS 到期。
M. 大题库读取与排序可在合理时间内完成；每次启动不扫描全部跨集历史，输出有缓存/失效证据。

## 11. 模型调优与反事实验证（后续）

把所有阈值和权重存为版本化规则常量。先用合成场景和已有历史的离线回放（须获授权并去隐私化）比较 `legacy` 与 `adaptive-v2` 的优先级差异、覆盖率、超时、重错率和严重逾期服务率。指标确定后再调 half-life、重复惩罚和知识风险权重。不能把规则指标当作已训练模型、已证实最优算法或真正预测概率。探索性模型不得自动写回 FSRS 参数。
