# 独立草稿箱、子页面安全返回与桌面弹窗

> **状态：待实现。** 来源：[#20](https://github.com/Aides8Stack/GankSoft/issues/20)、[#22](https://github.com/Aides8Stack/GankSoft/issues/22)、[#23](https://github.com/Aides8Stack/GankSoft/issues/23)、[#24](https://github.com/Aides8Stack/GankSoft/issues/24)，关联最新草稿合同 [#19](https://github.com/Aides8Stack/GankSoft/issues/19)。
> 所有切页/返回必须遵循**用户未明确保存/发布之前仅内存缓存**的新规则。

## 1. 「草稿箱」必须是独立子页面

- 卡片集的“草稿箱”和编辑页右上角“草稿箱”，都进入同一个独立草稿管理子页；**不得**把草稿缩成“所有卡片”表格上方一排标题按钮。
- 只显示用户**明确点击过保存草稿**形成的持久记录；未提交的内存编辑内容不入草稿箱。
- 列表可见字段：草稿标题（空标题有明确占位）、所属卡片集、卡片类型、新卡草稿或已发布卡修改草稿、更新时间/当前状态；支持搜索、分页，明确“继续编辑”“删除草稿/放弃修改”。
- 草稿箱的「← 返回上一页」返回进入它之前的**真实页面**，如原编辑卡、所有卡片、卡片详情；不能永远固定“所有卡片”。列表筛选/滚动/分页状态尽量保留。
- 草稿箱 → 继续编辑某草稿 → 「取消/返回上一页」应返回同一草稿箱；返回原编辑页面需维持正确 deckId/cardId。

### 删除/放弃草稿的不同语义

- **新卡未发布草稿：** 删除/回收的是未发布草稿及关联非正式暂存数据，不能留下孤立的持久空壳/媒体/错误引用，尽量沿用设置回收站的安全恢复语义。
- **已发布卡的修改草稿：** “放弃未发布修改”**不能删除原正式卡片**，不能损坏已发布 ContentVersion、学习记录、FSRS/周期和有效媒体/知识点引用。
- 删除前必须明确确认；并发编辑、revision 冲突、异步媒体、未知回执、操作重复点击要保证事务/幂等，不可出现草稿被旧自动保存回调“复活”。
- 目前公开草稿 API 没有独立安全删除命令，不能仅在 UI 隐藏条目伪装删除或拿正式卡片删除 API 替代；要建立正确的删除事务/协议和读回验收。
- 点击发布成功，关联草稿按 [CARD-DRAFT-PUBLISH.md](./CARD-DRAFT-PUBLISH.md) 的**同事务清理**规则从草稿箱消失；不是用户另点“删除草稿”才能发布。

## 2. 全部非主导航页面统一返回来源

- **导航栏直达的一级主页面**：不强制再加返回按钮。
- **所有二级或更深子页面**：页面显眼位置有「← 返回上一页」或符合业务语义的「取消（返回）」；包括卡片编辑、草稿箱、卡片详情、单卡调度、知识点子管理、各类导入/导出预览页面。
- **编辑卡片页底部**在保存草稿、调度设置、重新开始学习、发布卡片所在工具行加入「取消」；顶部原有返回入口保留，两者必须复用同一安全离开逻辑。
- 编辑 → 草稿箱 → 返回 → 原卡编辑；编辑 → 单卡调度 → 返回 → 原卡编辑；草稿箱 → 编辑草稿 → 返回 → 原草稿箱；筛选列表 → 卡片详情 → 返回 → 原筛选列表。
- 需要维护真实来源路由/面包屑栈、deckId/cardId、列表筛选/分页/滚动/选中。若来源失效或从深链接打开，安全回退到相关一级页，避免死循环。
- 对话框有明确的「取消/关闭」，支持 Esc、焦点恢复；不能用浏览器历史简单代替保存保护。

### 离开有未提交编辑的页面

- 任何返回/取消/切页/关闭在有未提交修改时，先给三种选择：**继续编辑 / 放弃本次未保存修改并返回 / 保存草稿并返回**。
- 只有用户**主动选择“保存草稿并返回”**时才能写库；保存失败或结果未知应保留原编辑页、编辑内容与可核对入口，不静默丢弃。
- 用户选择放弃时，如果此前曾手动保存过旧草稿，只丢弃**这次未提交修改**，原已保存草稿保留；无修改时可直接返回。
- “取消”是离开编辑器操作，不是删除草稿，也不是一定清空当前卡内容。
- 统一所有入口而非只有底部取消有确认、顶部返回却自动保存；退出或异步页面切换也不能绕过保护。

## 3. AI Prompt 与粘贴卡片预览弹窗尺寸

- “复制外部 AI Prompt”是内容阅读型弹窗：桌面宽度建议 **720–860 CSS px**；“粘贴卡片预览”建议 **760–920 CSS px**，不能沿用普通小确认框宽度。
- 高度由视口约束，建议参考 560–700 CSS px 但不超过可用桌面空间；响应式最大宽度参考 90–94vw、最大高度参考 85–90vh，保证 1366×768、900px 内容区、Windows 125% 缩放不溢出。
- 配置/标题、长文本预览/编辑、底部操作应分区；中间主要阅读区占较大比例并内部滚动，确认/取消/复制始终可达。
- 保持粘贴结构化预览、解析/图片、安全检查，Prompt 知识范围选择、文本复制等原业务合同不变；本项**只改善可用尺寸与交互**。
- 源码定位：`src/cards/CardDraftForm.vue` 对话框、`src/unified/UnifiedWorkspace.vue` 页面切换，及相关组件样式。

## 4. 定向 GUI 验收

- 分别从所有卡片、草稿箱、编辑、调度、筛选进入子页面，再返回，核对真实来源、deckId/cardId、列表状态与是否误写 SQLite。
- 新建/已发布卡有内存修改时：尝试顶部返回、底部取消、切页、Esc/退出；三选确认完整，放弃不写库，显式保存才写库；重启后数据库一致。
- 新卡草稿/已发布修改草稿的“创建→草稿箱→重开→删除/放弃→重启恢复状态”；删除后的原正式内容/学习历史未丢。
- Prompt 和粘贴预览在 1500×900、1366×768、900px 及 125% 缩放测试尺寸、滚动、焦点、复制/确认/取消行为。
- 不以 API 单测代替真实 Electron GUI；Win10/11 未实机测试前保持未验状态。
