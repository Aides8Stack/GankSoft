# GankSoft v0.7.6 — UI + 后端全链路强制验收合同（2026-10-27）

## 用户最终验收决定

**每一个 UI 页面、按钮、操作入口都必须测试真实前后端功能，而不是只查看外观或组件存在。** v3.7 HTML 原型是视觉和布局权威；正式 Vue/Electron 连接 Schema606 的真实业务服务。合格要求为：**原型视觉一致 + 正式 UI 可交互 + 真正调用既有 API/IPC + 业务结果正确 + 数据写入/读取/重启持久化正确 + 错误/取消/安全边界正确 + 必要回归未削弱**。任一关键层面 NOT_RUN/FAIL/BLOCKED，则该页/阶段不得标 DONE。

## 测试层级（必须分别报告）

1. **视觉层**：同宽同字体同缩放原型 vs 正式生产 Electron，1500/1366/900，空白与合成非空状态，缺区块不能 PASS。
2. **UI 行为层**：点击、Tab/焦点、导航、选中态、无数据/异常、弹窗、取消/确认；真实 Electron 主进程，不只 DOM mock。
3. **API/IPC 契约层**：preload `gank.protocol`、网关输入/输出、权限/范围/修订冲突；测试输入真实命中服务，不只 spy/mock。
4. **数据库与业务层**：隔离临时 Schema606 SQLite、FSRS/学习事件、媒体、知识树、事务、只读聚合、历史。对实际持久状态做断言。
5. **重新启动/恢复层**：写入后退出并重开正式 Electron，再读取验证；包括草稿、历史、知识图谱、队列及备份恢复。
6. **回归/安全层**：受影响模块旧测试不能删除/弱化/skip/continue-on-error，必要整套回归按既有强度执行；失败修复后复跑。
7. **Windows 平台层**：PR CI 的 Windows 质量与正式 EXE UI 不同；Windows 真实正式截图/人工 Win10/11 仍须独立证据，不得拿 Linux 代替。

## 强制通过条件与报告格式

阶段 `DONE` = 关键视觉、UI、API、数据库/重开、相关回归、真实 Windows 证据都 PASS（不适用项需明确说明理由），并已提交源码、测试、数据协议证据和截图至 GitHub。未跑写 `NOT_RUN`；环境阻断写 `BLOCKED`；失败写 `FAIL`，不得记作全部通过。

每个页面/场景必须写下：
```
页面/版本SHA/操作系统/Node/Electron/宽度/数据集：
操作步骤和预期视觉：
用户动作 → Vue 组件/回调 → protocol 方法 → 服务/SQLite/FSRS/媒体 → 实际回执：
数据库最终状态（含是否应无副作用）与事件/回执/资产：
退出重开后恢复结果：
空态/非空/失败/取消/重复/并发的真实断言：
关联回归命令、退出码、通过数、失败数；未运行原因：
VISUAL=PASS/FAIL/BLOCKED/NOT_RUN
UI_INTERACTION=PASS/FAIL/BLOCKED/NOT_RUN
API_INTEGRATION=PASS/FAIL/BLOCKED/NOT_RUN
DATA_PERSISTENCE=PASS/FAIL/BLOCKED/NOT_RUN
REGRESSION=PASS/FAIL/BLOCKED/NOT_RUN
WINDOWS_REAL=PASS/FAIL/BLOCKED/NOT_RUN
阶段=NOT_STARTED/IN_PROGRESS/BLOCKED/DONE
```

## 运行边界
所有测试使用明确的合成数据与隔离临时库；严禁使用真实私人学习数据库、上传个人内容或隐私截图。已有通过证据可继承，但仅当被测代码/环境未实质变化；涉及导航/界面/调用路径变更的关键场景必须补测。不要为了减少额度无限重跑全量测试；先按影响范围跑关联，再在阶段 gate/交付点跑约定全量。**不允许凭截图或 UI 事件断言替代后端持久化验证。**
