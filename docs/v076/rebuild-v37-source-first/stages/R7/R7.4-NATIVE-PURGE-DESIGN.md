# R7.4 原生606永久删除：合同边界与安全协议

## 已核实的真实合同

- `electron/infrastructure/migrations/unified-schema.ts`：`learning_cards`与`learning_content_versions`/`learning_study_cycles`存在双向外键；`learning_review_events`还引用版本和周期。版本、周期、事件各有禁止UPDATE/DELETE的不可变触发器。即使卡片没有复盘事件，已发布卡片也已经有受保护版本和周期。
- `cards-unified/lifecycle.ts`执行软删除/恢复，保留身份、草稿、历史、图片及排期；`workspace-unified/recycle.ts`是随集软删除/恢复；`knowledge-unified/recycle.ts`存储子树回收批次和删除时修订，恢复按完整快照/树指纹校验。
- `modules/trash.ts`的旧purge枚举question/memory等旧对象，不覆盖原生learning_cards；不能用于统一永久删除。未注册任何新的purge命令，也未调用旧trash.manage、移除触发器、关闭外键或删除历史文件。

## 本轮已可执行的安全部分

`recycle.native.preview`是已注册的严格类型**query**，输入为cards（逐卡expectedRevision）、deck（expectedRevision）、knowledge（batchId，服务逐节点验证回收时修订）。服务要求606，校验所属集、删除状态/修订/批次、重复/范围上限；用纯读事务获得一致视图。输出包含真实对象ID/名称/修订，发布版本/周期/事件/草稿/排期/页面与保留引用文档计数、图片身份引用、数据epoch和范围fingerprint。

卡片集范围也包含未发布草稿，不能以没有learning_cards行漏掉。前端给三种对象提供正式Electron模态预览、三宽滚动、关闭/Escape/焦点返回。所有结果固定`execution=blocked,filePolicy=retain-all`；fingerprint**不是执行token**，不能重放为删除授权。预览未执行文件I/O或实际资源清理。计数覆盖列明的原生/保留记录，**不是可直接执行的全部旧表级联清理清单**；正式执行合同确定后仍须遍历旧投影、故障/调度事件、历史快照等传递依赖。不能因为当前界面展示计数就声称永久删除合同完成。

通过纯读事务绕开写事务的beforeOwnedCommit所有者维护写入；领域测试额外断言`total_changes()`不变、逐表/附件字节不变，过期/跨集/重复选择拒绝，恢复后原范围不可用。前端原生预览关闭与恢复取消零写，恢复成功刷新列表，正常退出新PID读回。Windows原生系统确认框可见性未验收，另归B02/R8。

## 待用户决定的不可变历史语义（执行阻断）

必须明确“永久删除”具体选择，不能由实现者自行决定：

1. 保留不可变学习历史/发布内容/必要最小身份，永久取消恢复能力，只清理允许删除的可变内容。需要明确其是否应称为“永久归档”，以及历史查询/统计/备份中仍可见哪些信息；不是物理删除learning_cards。
2. 真正销毁卡片及所有不可变内容/历史。涉及已声明不可变合同和Schema606迁移，必须另获明确授权、设计新schema及旧备份/导入处理；本轮未实施。

知识点也必须决定其回收批次、历史快照中名称/关联、合并来源和引用图片是否继续保留。卡片集还需决定未发布草稿与先前独立删除内容是否纳入。当前默认全部保留，不静默选择任一产品语义。

## 决策后的执行协议设计（尚未注册/运行）

- 新的原生preview生成短期、作用域绑定的服务端token，绑定schema、数据epoch、逐对象revision、完整依赖闭包与文件SHA。请求需显式历史策略和选择对象，限制数量/递归范围；对活动会话、共享/跨集引用、不完整范围及不可变保护明确拒绝。当前fingerprint不能代替此token。
- typed command只接受该token、明确风险确认和固定requestId；事务内重新校验epoch/revision/全部依赖与媒体引用，防止预览后并发更改。协议网关沿用现有回执、幂等和未知结果原ID核对，不增加平行事务/回执系统。
- 所有允许的数据库变更、回收记录和待清理资源清单在同一事务提交；注入任意语句/回执失败应逐表回滚。未获授权的历史记录永不进入DELETE列表。
- 文件清理必须提交 durable receipt 后后置执行；复用媒体退役的全库引用检查、资源身份/路径白名单、拒绝符号链接/目录逃逸/共享文件、重复执行无害与失败留存字节的策略。不能在事务提交前rm文件，也不能把“没有当前引用”等同“没有历史引用”。
- 验证清单：确认/取消零写、并发过期、跨集/混合范围、活动及归档会话、共享图片/历史/回收引用、SQL/回执/文件故障、同请求重放、新进程读回、最终外键/完整性校验与备份恢复合同。未实现执行协议，这些执行项固定NOT_RUN。

本设计不批准任何不可逆销毁，不进入R7.5/R8，不改变Schema606/FSRS/历史合同。
