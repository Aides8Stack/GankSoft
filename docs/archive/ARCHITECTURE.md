# 模块化架构

## 技术决策

一个 Electron 桌面程序、一个 SQLite 数据库。界面和业务使用 TypeScript。MVP 直接使用 `node:sqlite` 和版本化 SQL 迁移，减少 ORM 与原生 Node 插件依赖；后续可以在数据层替换为 Drizzle，不改变界面调用协议。

Electron 主进程拥有数据库、文件操作、模型连接与备份；Vue 渲染进程仅通过 preload 暴露的受控接口访问。预加载为 sandbox 可加载的 CommonJS 文件，开启 contextIsolation，关闭 nodeIntegration。窗口禁止额外窗口和任意导航，界面不加载 CDN 脚本。

## 目录与职责

| 目录                         | 职责                                                 |
| ---------------------------- | ---------------------------------------------------- |
| `electron/modules/knowledge` | 知识点、层级、相关关系、合并删除                     |
| `electron/modules/questions` | 错题、公共材料引用、图片引用、计划操作               |
| `electron/modules/review`    | 评分、排期纯函数、复盘保存                           |
| `electron/modules/ai`        | 模型请求、输入校验、超时与错误处理                   |
| `electron/infrastructure`    | 数据库、事务、备份和共用上下文                       |
| `electron/application.ts`    | 命令入口、跨模块事务协调、快照与分析查询             |
| `electron/main.ts`           | 桌面生命周期、系统对话框、剪贴板、受控文件协议、密钥 |
| `shared/types.ts`            | 共享数据结构与枚举                                   |
| `src/components`             | 按业务功能拆分的界面组件                             |
| `src/store.ts`               | 页面状态与统一刷新、消息反馈                         |
| `tests`                      | 关键业务不变量与备份测试                             |

九个学科模块共用错题／知识点／复盘能力，不复制九份代码。科目区别通过 module 字段及专用功能扩展。

## 调用流程

组件 → `window.gank.call` → preload IPC → Application → 业务服务 → SQLite。

所有普通写操作由 Application 在同一个事务中执行。图谱与列表共用知识点服务。备份和恢复期间阻止普通写操作；用户操作失败时返回明确错误，不静默丢弃。

## 数据约束

- 知识点和错题使用稳定 UUID。
- 同模块同父节点下，存活知识点名称唯一。
- 错题知识点关联使用联合主键。
- 相关连线两端按 ID 排序，保证无向关系唯一，禁止自连接。
- 父节点只能在同模块中，业务层检查循环。
- 外键启用，数据库事务确保合并／删除不产生部分结果。
- 可编辑记录使用 version 防止旧编辑框覆盖新内容。
- 历史错因保留知识点名称快照；合并可迁移当前引用，快照不篡改。
- 修正正确答案后重置复盘计划与掌握分，保留历史答案快照，重新验证。

## 修改与升级

调整界面改对应 Vue 组件；调整排期改 scheduler 及其版本；更换模型改 AI adapter；知识点操作规则集中在知识点服务，不能在图谱组件写 SQL。

增加数据库字段时：提升 schemaVersion，新增顺序迁移脚本，迁移前生成完整备份，验证旧数据升级。当前包含 v1 初始结构和 v2 记忆／导入／存档迁移；更高版本数据库会拒绝以旧版打开。

申论后续新增独立业务模块，复用附件、备份、模型连接；不污染行测的题目与作答模型。

## 扩展时注意

MVP 以全量快照简化页面状态，初期可维护。题量大后应按模块分页查询，图谱按局部关系加载，统计改为 SQL 聚合；接口层允许逐步替换。大量 OCR、批量导入等 CPU 工作应引入后台 Worker，避免阻塞主进程。

备份使用 SQLite 一致性快照；附件按应用分配的 UUID 文件名读取，恢复检查校验和、外键与文件完整性，不接受路径穿越。AI 连接配置与密钥不包含在备份中。

## v0.2 新模块

- `electron/modules/memory`：政治理论和常识的积累、自评与排期。编辑版本与记忆内容版本分开，修改标题不增加同日有效复盘。
- `electron/modules/imports`：数据协议验证、只读预览、稳定编号映射、并发修订检查、跨模块事务与附件失败清理。
- `electron/modules/knowledge/archives.ts`：科目当前图谱发布为不可变版本、导出版本。历史快照与可编辑知识点分离。
- `shared/import-protocol.ts`：便携交换协议的数据类型。
- `src/components/MemoryWorkspace.vue` 与 `ImportWorkspace.vue`：独立业务界面。

知识点合并同时迁移记忆卡关联与外部 key 绑定；历史存档保持原样。导入修改需用户在软件预览确认，不将同名或相似词自动合并为同一知识。
