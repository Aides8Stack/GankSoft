## 3. 完整实施顺序（持续推进但分阶段可恢复）

### P0 — 真实入口、视觉基线、全局设计系统
1. 验证正式生产 app 根组件实际使用 `UnifiedWorkspace.vue`。定位当前用户截图的默认按钮/稀疏大空白根因。
2. 将 v3.7 的 token（以原 HTML 实值为准）、控件规范和布局结构移植到正式 Vue 工作台，做独立命名空间，如 `.gank-v37`；全局 CSS 只做经审查的必要调整。不要直接把 `.v04` 强套到 `.unified-shell`，避免旧 604 风格覆盖。
3. 统一按钮、搜索、表单、标签、卡片、列表、空状态、信息层级、页面标题、导航态、键盘焦点、悬停中文 tooltip；处理 global `select{width:100%}` 等样式冲突。
4. 窄图标栏保留，采用原型顶部导航/二级导航的信息层级；卡片集入口通过明确的集合选择器/导航，不要变回 213px 常驻宽栏。
5. 设定布局断点，重点验证 1500、1366、900 宽，内容紧凑但不挤；图谱例外使用全屏工作台。

### P1 — 学习总览（最优先改好真实首页）
1. 按原型页面结构实现：页面标题+说明+新建集、四个摘要指标（卡片集数、总卡数、今日待复盘、今日完成）、“我的卡片集”列表、继续复盘、最近学习。
2. 接入真实 606 数据；统计字段若现有模型不支持，先查现有只读统计服务，必要时增加**最小、独立、分页/聚合只读 API** 并附证明，不增加数据库表或扫描全量卡片到前端。
3. 真实空白 DB 下显示与原型视觉一致的优质空状态：0 数值、创建引导，不出现丑陋的默认 HTML 按钮堆叠/大片无结构空白。
4. 树形文件夹管理、集列表/进入/新建/编辑/导入保持真实可用；卡片集本身不包含子集。
5. 从首页进入某卡片集应进入 **该集概览工作台**，不是直接跳进纯表格列表。

### P2 — 卡片集主页、卡片列表与详情
1. 按原型的本集标题/概要、指标行、学习计划主区、快捷入口、最近卡片与复盘概况双栏，实装 `deck overview`；从本集进入卡片、复盘、分析、知识图谱、设置等。
2. 卡片列表：搜索+筛选同一合理工具带、状态/类型、知识点摘要、最近得分/用时/复盘次数（仅在真实可查询时呈现）；多选后工具栏、详情与编辑明确分离。
3. 保持真实单选错题、问答记忆、直接记忆三种发布卡片能力及原历史映射；不要从原型临时演示模型倒推或修改业务类型。
4. 懒加载摘要和卡片详情；列表分页，不一次加载全部题目大字段和图片。

### P3 — Markdown 编辑、复盘、分析
1. 编辑器沿原型页面视觉结构/知识点关联方式组织真实三模式卡片；保留 Milkdown/Crepe、LaTeX、图片缩放/粘贴、自动保存及 Ctrl+S。按需展开大编辑区域，不堆多个长表单；类型切换继续遵守草稿清空/确认语义。
2. 复盘 UI：顶部多会话标签、进度/计时与暂停、题目优先、选项及答案揭示、自评分/原始思路/错因/知识漏洞与复盘历史。不改 FSRS Again/Hard/Good/Easy、答错 Again、总计时及离开自动暂停规则。
3. 学习分析：按原型 KPI、图表与知识点掌握列表展示**真实已计算指标**；不能靠演示硬编码。没有数据时显示真实空态并说明；可按现有只读模型分批获取数据。

### P4 — 知识图谱/Markdown 工作台（全部补充设计生效）
1. 正式卡片集知识图谱使用真实 `MindMapWorkspace.vue` + Mind Elixir，铺满应用工作区，不是固定 620px 画布；宽窄窗均无留白和溢出。
2. **空白画布左键平移**；节点选择/双击修改/Tab 子节点/Enter 同级节点；普通节点支持同级排序及变更父子层级；多根节点支持。**根节点拖动整张图的手势暂缓，不作为验收点**。
3. 工具栏图标化+中文 tooltip，搜索、撤销/重做、展开/折叠、定位/适应、全屏等保持一条连续工具带；**新增子节点、同级节点按钮紧跟“全屏”按钮后面**，1500px 宽不跑到最右侧、900px 宽合理换行，悬停/键盘聚焦均有提示。
4. 选中节点右侧轻量详情，无重复树导航；MD 正文真实持久化、公式/图片、自动保存，右侧 MD 大纲按父子关系显著缩进（18px 级差或等价）。
5. 导入：左边图选择挂载节点、右边来源/大编辑区、差异预览/确认；导出：全图/局部，先选节点后出现复选项。拖动/删除子树进回收站/恢复重名缺父/掌握度汇总/当时知识快照等全部保留。

### P5 — 设置、回收站、系统入口与全局完善
1. 设置与回收站独立于卡片集普通功能区，页面返回原处；数据目录/备份/导入导出仍沿用正式 606。
2. 保留强确认删除、恢复、文件选择取消处理；小屏/高 DPI/空态、禁用态、加载态、错误信息和键盘导航。
3. 全局 CSS 和 scoped 样式互不污染；禁止旧页/测试宿主视觉冒充正式页。

### P6 — 正式 Windows 验收、必要修复、交付
1. 自动化基线通过后，**必须在 Windows 10/11 x64 的正式 Electron 生产入口/打包 EXE** 截取中文页截图，至少覆盖 P1–P5 主要视图、原型空态和含合成数据的非空态，宽度 1500/1366/900 附必要交互状态。
2. 截图须说明：`sourceSha`、`buildSha`、`runId`、启动方法 `production-main`/`packaged-exe`、屏幕分辨率、真实/合成数据隔离标志；不能用 `card-draft-spike`、旧 604 宿主、静态原型截图冒充正式软件。
3. 对照原型逐项判定：相同的内容分区、层级、紧凑度、视觉 token、工具栏位置和交互；根据 `03-ACCEPTANCE-MATRIX.md` 标记 PASS/FAIL/BLOCKED/NOT_RUN，保存对应图片和验证操作日志摘要。
4. 如果没有 Windows 环境，Linux 验证可以推进工作，但**最终 Windows UI 验收必须明确标为 NOT_RUN，不允许说 UI DONE**。安排由现有可信 Windows runner 采图、或用户在最终 ZIP 的 Windows 客户端做人工确认。
5. UI PASS + 必要业务回归 + 安全门禁 PASS 后，走受保护 PR（必要时版本从已合并 `0.7.5-rc.2` 正常递增，先检查已有版本/tag）并由所有者审核再合并。便携 ZIP 仍走现有 develop 流程；**不自动合并、不批准或发布 Release**。
