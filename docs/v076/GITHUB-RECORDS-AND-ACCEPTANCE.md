# GankSoft v0.7.6 — GitHub 永久记录及正式 UI 验收规则

此文档由用户 2026-10-27 的新版本决定授权。**设计、源码、测试、验收和阶段状态须在 GitHub 实际远端可追溯**；只存本地 Work、一次性截图窗口或短期 Actions Artifact 不算完成。

## 目录规范

- `docs/v076/WORK-PLAN.md`：原型直接落实总体计划/阶段范围；改动计划时维护变更原因和所有者决策。
- `docs/v076/STATUS.md`：P0–P6 状态总表、最近已核实远端检查点、当前唯一下一步、PR/CI/RC状态。
- `docs/v076/stages/P0/` … `P6/`：每阶段 `PLAN.md`、`PROGRESS.md`、`TEST_REPORT.md`、`ACCEPTANCE.md`；如有截图则放 `evidence/`，至少有索引说明图像来源和分辨率。
- `docs/v076/adr/`：只有真实设计与现有规范冲突或最小 API 扩展时才新增简短决策记录；不要重复写同一份说明。
- 源码和真实测试直接放 `src/`、`tests/`、`tools/` 等本来路径，提交里按 P 编号归档；不要把测试源码只拷到文档目录。
- `docs/development/` 保持任务级恢复文件 `TASK.json`、`PLAN.md`、`PROGRESS.md`、`HANDOFF.md`、`TEST_REPORT.md` 与版本阶段一致。按 AGENTS.md 初始化新任务并归档旧任务，不重置别人 WIP。

## 每个阶段的强制证据（不得仅填 PASS 字样）

1. 设计：原型具体区域/控件/状态及后续补充决定，说明映射的正式 Vue 组件、实际布局对比与异常。
2. 实现：相应提交、修改文件、必要 API 调用/数据绑定，说明没有硬编码演示数据；必要时留组件树、约束和简短 ADR。
3. 测试：命令、环境、开始状态、测试规模、真实退出码、失败项目和被测完整 SHA/工作树；区分本地 Linux / Windows runner / 人工 Windows10/11。
4. UI：原版 v3.7 对照图和**正式生产 Electron** 同页中文截图，说明屏幕宽度 (至少 1500/1366/900 的相关页面)、空白606与合成非空606、sourceSha/buildSha/runId/执行入口。可用压缩 PNG/WebP（存仓库的非敏感截图），不可用旧604/测试 spike/静态原型冒充。
5. 接受性：逐项 PASS/FAIL/BLOCKED/NOT_RUN；对 FAIL 记录最小修正与回归，而不是因为 CI 绿就自动通过。
6. 远端：提交并 push 成功后再次 fetch/读取远端 tree、完整 SHA、PR 关联状态和检查结果。若推送失败状态必须为 ONLY_LOCAL/BLOCKED，不得假称同步。
7. 恢复：写明唯一下一任务、剩余风险、用户需做的动作；不等待长 CI 才存档。

## 版本与权限

- `package.json` 与 `package-lock.json` 的根版本必须同步，目标首个 RC 为 `0.7.6-rc.1`；后续递增 RC，不直接伪造 0.7.6 Stable；同时更新构建源身份与报告标签，不能靠改 zip 文件名冒充。
- 修改 `package.json` / `package-lock.json` 会触发已有 **pr-trust owner 按完整 SHA 复核**；不得删文件、修改工作流绕过审核或假造信任状态。
- 不自动合并、发布 Release 或审批信任；用户批准后才推进。
- 公共仓库中禁止上传密钥、真实学习库、隐私图片、未经脱敏的日志/Windows 用户目录路径、构建完整依赖包。代码、设计、非敏感记录、测试脚本和小量确认过的截图可推送。
- Windows GitHub CI 自动化不能替代用户 Win10/11 同包人工验收；未手工执行仍为 NOT_RUN。
