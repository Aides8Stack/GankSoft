# 卡片、草稿与列表（cards） — v0.7.7 真实 GUI 使用路径与反馈测试

> **未运行的测试不得写 PASS**。关联原 CASE 组：NEW、OLD、LIST；本模块的机器可读配置在 `tools/validation/v077/modules.mjs`。此文件只记录正常和异常路径的预期，不复制第二套结果账本。

## 正常使用主链

三类型建卡→自动/手动草稿→草稿箱→合法发布→列表→编辑旧卡→重启。

**必须有的反馈：**保存中/草稿已保存/发布成功/缺少正确答案/保存冲突。

**必须读取的结果：**cardId与内容版本正确、草稿可找回、历史不变。操作后必须验证页面同步、正常离开与返回；持久化写操作还需独立新 Electron PID 重启读回。

| CASE ID | 从用户可见页面触发的操作 | 必须看到/核验的结果 | 当前 Electron 状态 |
| --- | --- | --- | --- |
| NEW-01 | 新建错题复盘卡 → 只键入标题/题干 → 不点保存 → 等待自动保存状态 → 返回列表 → 点击草稿箱 → 选择卡 → 重启后再恢复 | 草稿 UI 和持久化正文与标题精确一致，未发布卡不进入正式卡表 | PASS |
| NEW-02 | 新建问答记忆卡 → 只输入问题 → 不点保存 → 返回 → 草稿箱 → 再进 → 重启 | 问答草稿及类型保留 | PASS |
| NEW-03 | 新建直接记忆卡 → 只输入记忆正文 → 不点保存 → 返回 → 草稿箱 → 重启 | 直接记忆草稿及正文保留 | PASS |
| NEW-14 | 点击保存草稿/按 Ctrl+S → 草稿箱 → 重开 | 显式保存与自动保存同一合同，不创建第二份草稿 | NOT_RUN |
| NEW-16 | 草稿未满足发布必填字段 → 尝试发布 | 拒绝发布但草稿仍可自动保存并在草稿箱找回 | NOT_RUN |
| NEW-17 | 草稿新增编辑 → 正常发布 → 回列表/草稿箱 | 唯一正式卡片、正式内容正确，不产生第二个学习卡 ID | NOT_RUN |
| OLD-01 | 打开已发布错题卡 → 修改题干 → 不点保存 → 返回 → 草稿箱 → 点击恢复 → 重启 | 同 cardId 的修改草稿精确存在，正式版本保持原文 | NOT_RUN |

| OLD-11 | 发布后返回草稿箱/卡片列表 | 旧草稿移除或按明确状态处理，卡片数量与 ID 不重复 | NOT_RUN |
| LIST-01 | 已发布卡进入所有卡片 → 按标题关键词搜索 | 只显示匹配项，清空恢复全部 | NOT_RUN |
| LIST-02 | 按卡片类型过滤、排序复盘次数与标题 | 结果与持久化元数据一致 | NOT_RUN |

## 异常、取消与用户反馈

| CASE ID | 失败/取消/特殊输入 | 反馈或零写断言 |
| --- | --- | --- |
| NEW-18 | 触发草稿保存失败 → 输入并返回 | 不能假装已保存；保留可恢复正文并允许重试 |
| OLD-14 | 草稿处于保存冲突/未知回执 → 快速再按发布 | 不允许重复或跳过核对，明确阻断 |

通用五态：**未保存 → 处理中 → 真成功 → 可理解的失败/冲突 → 空结果/取消**。收集失败时必须分别记录用户所见、后台确认和重启后结果，不能只记录报错字符串。
