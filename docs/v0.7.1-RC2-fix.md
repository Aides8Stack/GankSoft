# v0.7.1 RC2：Windows 原生图片插件启动故障修复

## 用户反馈与定位边界

用户运行原v0.7.1 RC Windows包时，主进程在启动阶段报“Cannot find native binding”，未进入界面。该包SHA256：86e063d62c37723d63a566325f4e0df7e03e07937f99a020dc4f6d8c3bbafc24。此前Windows运行时/资源静态检查通过，不能证明原生模块能够在用户Windows上加载；本次用户反馈证明原包存在启动失败。

检查已确认：原打包目录含有MSVC原生插件，但最终ZIP没有任何app.asar.unpacked文件。交付压缩脚本错误地把源码排除规则应用到Windows运行目录，排除了app.asar.unpacked/node_modules整个子树；因此EXE启动时找不到必须在ASAR外加载的.node文件。这是本次交付错误，不能归因于用户漏装npm。

截图没有底层cause，但缺失文件已由原ZIP逐项核验确认。修复后的实际ZIP必须包含插件二进制、元数据及DLL，并通过独立检查器；Windows运行结果仍需实机确认。
## 修复内容

- 修正Windows ZIP压缩规则，完整保留app.asar.unpacked/node_modules；新增zip-windows.py与verify_delivery.py，强制检查最终ZIP中的原生文件、完整SHA256清单和CRC，不能仅校验压缩前目录。原ZIP在新检查器下应失败。
- 图片解码改为按需加载，启动阶段不再触发第三方原生插件加载；图片不可用不再阻止主界面、学习、设置和备份启动。
- Windows x64显式加载已打包的@napi-rs/image-win32-x64-msvc，避开上游自动加载器的Node构建标志推断；PNG/JPEG/WebP的完整解码、MIME及大小校验保留，未通过校验不会写入。
- 完整解包原生包目录，保留package.json与.node；将已校验的MSVC运行时同时放置在EXE和插件目录，覆盖两种DLL查找位置。
- 插件加载失败保留底层异常，在数据目录写image-decoder-diagnostics.log；返回IMAGE_DECODER_UNAVAILABLE，不把失败当成功。media.import在写入前的此类明确失败不会遗留待核对操作。
- 应用版本仍为0.7.1，修复构建标识RC2；不改变数据库schema601、v060/data或内容协议。

关键入口：electron/infrastructure/image-binding.ts、images.ts、electron/main.ts、electron/protocol/gateway.ts、tools/package-windows.mjs。旧包与原始源码保留用于追踪。

## 使用与验收

退出旧版，备份数据，将RC2 ZIP完整解压到一个新目录，再双击GankSoft.exe；不要只替换EXE或从ZIP内直接运行。不需要安装npm、Node或删除用户数据。

先确认主界面可打开，再导入一张PNG或JPEG验证图片路径。若图片导入仍失败，应用会保留可用界面并生成image-decoder-diagnostics.log；诊断文件位于实际用户数据目录v060/data中（常规Windows为%APPDATA%下的GankSoft或ganksoft目录，以实际目录为准）。该日志可用于确定底层DLL/文件加载原因。Windows10/11完整人工验收按原v0.7.1-windows-acceptance.md执行，不能复用旧包结果。
