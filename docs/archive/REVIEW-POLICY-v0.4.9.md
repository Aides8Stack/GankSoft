# v0.4.9 多次复盘与单卡间隔验收

## 产品规则

“三次”是 v0.4.8 验证记录独立性的最小测试样例，产品从未按三次结束复盘。每道题可持续复盘，无次数上限；本版以连续 60 轮作为新增压力回归样例，60 同样不是功能上限。不能仅凭固定次数判断某题掌握或停止学习。

| 项目 | 行为 |
| --- | --- |
| 累计复盘 | 统计该卡全部已保存记录，包含旧内容版本 |
| 有效复盘 | 计入调度的记录；明确练习、部分同日巩固及提示学习不计入 |
| 练习／同日巩固 | 已保存但不改变正式排期的记录；累计次数仍增加 |
| 单卡最大间隔 | 1—365 的整数天，题目项目页或记忆卡详情设置 |
| 未单独设置 | 沿用全局默认值，初始为 60 天 |
| 已单独设置 | 覆盖全局默认值，可比默认值更短或更长 |
| 调小上限 | 以最近有效复盘时间为锚点，提前超过上限的现有计划及 FSRS due；已到期任务不会推迟 |
| 调大上限 | 保留现有较早的 due；下次有效复盘使用新上限 |
| 首次学习 | 未复盘的新卡保留现有首次学习时间，不因设置而增加记录 |
| 暂停 | 配置变化保持暂停状态 |
| 历史 | 修改上限不修改历史复盘或原始调度事件，不伪造复盘 |
| 备份 | 完整备份保存配置、历史和现有计划；内容交换包仍只交换学习内容 |

最大间隔限制的是两次调度复盘的最长间隔，并非固定周期，也不是最大复盘次数。FSRS 可根据表现安排更早的学习或复习。是否继续复盘应结合实际表现和需要，不给出通用的固定次数。

## 模块通信与存储

- `shared/review-contract.ts` 定义 `SaveReviewPolicyCommand`，字段为 `kind`、`card_id`、`max_interval_days`；null 表示继承默认值。
- `CardReviewPolicy.vue` 是题目与记忆卡共用的设置和统计视图，调用 `card.reviewPolicy.save`，不直接访问数据库。
- `Application` 统一处理命令和事务，返回是否提前了现有排期；快照的 `reviewPolicies` 用于显示已持久化配置。
- `review/policy.ts` 负责配置校验、单卡／默认优先级与现有排期限制。只接受有效卡片类型和存在且未删除的卡片。
- `review/fsrs.ts` 在每次有效复盘时调用同一配置解析函数。算法计算后再次限制 due，确保输出不超过用户上限；记录实际使用的 `maxIntervalDays`。
- schema 6 的 `card_review_policies` 以卡片类型与 ID 为联合主键，区分题目和记忆卡。卡片类型、天数范围由数据库 CHECK 约束；关联存在性由服务验证，永久删除由回收站模块清理。
- 调整配置与提前计划处于同一事务；失败全部回滚。配置操作写操作审计，原始调度事件保持不变。
- 内容编辑保留单卡设置；软删除／恢复保留设置，彻底删除清理设置；完整备份直接保存数据库中的配置。

## 审计发现和修复

现有逻辑没有三次复盘上限，但只提供全局最长间隔。新增单卡设置及次数汇总后，多轮测试发现 ts-fsrs 5.4.2 部分评分路径可能因间隔排序而超过 maximum_interval。修复方式是在算法返回后应用硬性时间上限，同步 card.due、card.scheduled_days 与当次日志 scheduled_days；保留稳定度、难度、次数等算法状态。降低设置时同步更新数据库计划与 FSRS due，避免界面和内部到期判断不一致。

## 验收结果

`npm run check`：74 项通过，类型检查及生产构建通过。新增 `tests/review-policy.test.ts` 包含 6 组测试：

| 测试 | 验证结果 |
| --- | --- |
| 同题和同记忆卡各连续 60 轮 | 分别保存 60 条记录，重试不重复，每轮原始记录独立，全部到期时间符合 7 天上限 |
| 重启与完整 ZIP 备份恢复 | 配置、120 条历史及调度事件、FSRS 状态一致 |
| 单卡上限变化 | 降低同步提前；提高不延后；暂停不变；全局变化不覆盖单卡设置；清除设置后继承默认 |
| 全局与练习 | 全局上限同时作用于两类继承卡片；练习不修改调度 |
| 校验与卡片生命周期 | 非整数、越界、错误类型、不存在卡片拒绝；修改内容、重启、删除恢复保留设置；永久删除清理 |
| 边界与失败回滚 | 1／365 天上限各经多轮评分；v5 迁移保持历史和排期；模拟计划写入失败后配置和状态共同回滚 |

`node tools/smoke-review-policy-v049.mjs`：真实 Electron 界面通过题目和记忆卡的保存、继承切换、次数分类、独立于全局、重启恢复及 980／1500／1920 像素宽度检查。

既有 `tools/smoke-reliability-v048.mjs` 继续验证原始思路草稿、请求响应丢失后的安全重试、版本冲突与备份恢复。
