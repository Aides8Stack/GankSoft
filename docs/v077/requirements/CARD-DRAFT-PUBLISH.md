# 卡片编辑、显式保存草稿与直接发布 — v0.7.7 最新合同

> **状态：B1 已实现且完成 Linux/领域新合同定向验收；Windows CI、Win10/11 实机 NOT_RUN。** 证据：`../fixes/B1-CARD-SAVE-PUBLISH.md`、`../evidence/B1-RESULTS.json`。独立草稿箱/全局导航仍由 B2 接续。 来源：[#16](https://github.com/Aides8Stack/GankSoft/issues/16)、[#17](https://github.com/Aides8Stack/GankSoft/issues/17)、[#19](https://github.com/Aides8Stack/GankSoft/issues/19)、[#21](https://github.com/Aides8Stack/GankSoft/issues/21)、[#22](https://github.com/Aides8Stack/GankSoft/issues/22)；需求日期 2026-10-30。
> 
> **优先级声明：** 以下“显式保存、保存允许不完整、发布未达标可点击显示提示”的最新规则覆盖旧的自动保存与“发布不足就 disabled”方案。

## 1. 数据生命周期（不得只修改界面文案）

- **新建新卡：** 仅初始化非持久编辑会话，打开时既不能建立持久空白草稿，也不能创建正式卡片；打字、粘贴、选择模式、选项变化，未点击保存/发布前只有内存缓存，重启不保证恢复。不可存在自动防抖写库或切页前静默写库。
- **编辑已发布卡：** 未明确提交的新改动只存在内存，已发布 ContentVersion、学习周期、复盘记录、FSRS、知识点和有效媒体引用均不受影响。
- **手动「保存草稿」：** 一次有效点击将当前缓存存成当前 cardId 对应的**唯一草稿**；第一次建立，下一次更新同一份，成功后独立草稿箱立即可见且可重新打开；不能出现未命名空白草稿自动无限增长。保存可不满足发布必填条件，**用户首次明确保存空白新卡也合法**，但结构/安全验证、修订号、事务和媒体约束必须通过。
- **手动「发布卡片」：** 发布当前内存内容，**不要求先保存草稿**；没有草稿时直接生成正式版本且全过程不留下草稿；已有草稿时在同一原子事务内创建新正式版本并清除对应草稿。失败、冲突、结果未知不得误删草稿、重复正式卡或显示已发布。已发布卡新修改正式发布时保留原有历史与调度语义。
- **离开/取消/崩溃：** 导航离开有未提交变更须确认，不能偷偷落库；崩溃/强制退出可能丢掉未提交内存内容，需如实提示。既有旧版自动草稿不可在升级时静默清理。

### 按钮与状态表（最终以**本表**为准）

| 实际状态 | 保存草稿 | 发布卡片 | 可持久化行为 |
| --- | --- | --- | --- |
| 新建空白卡、从未手动保存 | **可点击**：允许用户主动存空白草稿 | **可点击校验**；缺项只提示 | 打开页面/点击无效发布都不写库 |
| 新建有未提交修改 | 可点击 | 可点击：通过必填才真正发布 | 仅显式按钮提交 |
| 草稿保存成功、没有后续修改 | **禁用**，显示草稿已保存 | 可点击：必填通过则发布，缺项只提示 | 此时最多一份草稿 |
| 保存后又有新修改 | 重新启用 | 可点击校验/发布 | 新改动仍在内存 |
| 已发布卡打开、尚未再次修改 | **禁用** | **禁用**，已发布 | 原正式内容不动 |
| 已发布卡再次修改 | 启用 | 可点击校验/发布 | 原发布版本不动 |
| 保存/发布中、回执待核对 | 防重/安全锁定，显示准确状态 | 防重/安全锁定 | 不能重复建卡、重复版本 |
| 保存失败、发布失败/冲突 | 根据结果允许修复、核对、重试 | 按事务状态保护 | 内容与原草稿保留 |

**关键区分：** “资料不全时发布按钮可点击”不等于“允许不完整内容正式发布”；“草稿已保存”不等于“已发布”；“没有脏修改”不等于“刚收到保存回执”。

## 2. 发布必填字段及红色星号

| 卡片模式 | **发布前必填，标签后显示红色 `*`** | 非必填，不标星号 |
| --- | --- | --- |
| 全部模式 | 标题 | 所属卡片集（已有上下文，不因已有值另加必填视觉噪音） |
| 错题复盘（question） | 题干、选项（至少两个，内容均非空）、正确答案（必须实际选择有效选项） | 答案解析、我当时怎么想的/为什么错、公共材料、题目来源、知识点关联 |
| 问答记忆（qa） | 正面问题、背面答案 | 补充说明、题目来源、知识点关联 |
| 直接记忆（direct） | 记忆正文 | 题目来源、知识点关联 |

- 红色 `*` 只表示**发布**门槛。保存草稿时不读取这套发布必填校验，也不在控件上用原生 `required` 阻止草稿保存。
- 发布采用与后端同一业务规则：标题、卡片类型正文和正确答案检查一致；格式/安全/媒体约束无论保存还是发布都要满足。
- 后端拒绝时不能因前端显示星号而省略服务端核验；有明确中文错误反馈，不暴露原始技术异常文案。

## 3. 「发布卡片」缺项时的正中央短提示

1. **点击**发布按钮先对当前内存快照进行必要字段校验；校验通过才允许执行正式发布事务，不能在此之前先 `draft.save`。
2. 校验失败，软件内容区/视口**视觉正中央**显示**单个**半透明红色、圆角（约10–14px）提示框，不遮挡输入、不抢焦点、不滚动。示例：**“无法发布：缺少标题、题干、至少2个选项、正确答案”**。
3. 正常显示约 **1秒**，可短暂渐隐；用户**连续点击不完整的发布按钮**，每次都要重新出现/重置计时；新提示不能被旧计时器提前移除，不应堆叠多个 toast。所有校验失败点击对 SQLite、草稿、发布记录零副作用。
4. 后端冲突、写入失败、未知回执等**非必填错误**要提供持续可见的错误/恢复入口，不能只显示1秒后消失的 toast。
5. 中文可读、支持屏幕阅读器实时告知；不能仅用颜色表达语义。提示不会导致页面布局移动。

## 4. 保存确认与编辑安全

- 新建后未操作不显示笼统“已保存”，应显示“尚未保存/尚未编辑”；已发布卡只是打开查看应显示“尚未修改”。
- 明确点击「保存草稿」：在后台事务确认、revision/回执有效后显示“草稿已保存”与时间/可核对状态，提供「查看草稿」。没有本次写入时不能误报“再次成功写入”。
- 保存失败/冲突/未知结果保留内存数据，允许用户安全恢复/重试；不能只靠 `controller.state === 'clean'` 判断数据真实落盘。
- 同 cardId 的草稿和发布版本必须可追踪。草稿箱查询 UI 与 SQLite、重启后内容应一致。
- 普通文字粘贴不能被不必要的 `UNSUPPORTED_HTML` 拒绝；网页/Word 富文本安全降级或有效受控解析，不放行危险 HTML；验证粘贴异常后依然可正常保存草稿/直接发布。原始用户故障 [#16](https://github.com/Aides8Stack/GankSoft/issues/16) 与 [#17](https://github.com/Aides8Stack/GankSoft/issues/17) 的确切原因需用真实 Windows 测试证据闭环，不可用 Linux PASS 直接关闭。

## 5. 实现时需要改动的已知代码路径

- `electron/modules/cards-unified/new-drafts.ts`：当前 `createNewDraft()` 会持久创建空白 `new-card-draft:` 项，必须按显式存储合同重构。
- `src/cards/draft-controller.ts`：当前输入后定时 `flush()`；必须停止非用户授权的持久化，同时保证原 revision/冲突安全。
- `src/cards/CardDraftForm.vue`：当前发布前先 `saveAll()`，要改为**先本地发布校验 → 直接发布**；标题与内容必填标签、按钮状态、居中 toast、准确回执状态也在这里。
- `shared/protocol/card-draft.ts`、`electron/modules/cards-unified/publish.ts`、`shared/protocol/registry.ts`：发布输入目前依赖已有草稿修订；需设计**无草稿直接发布**与有草稿同事务清除的正式协议，继续沿用 Schema606，禁止假装前端直发而后台偷建草稿。
- `src/editor/milkdown-adapter.ts` 和 `src/editor/MarkdownEditor.vue`：需分别核验粘贴错误及失败后保存控制器的恢复边界。

这里只列出定位入口；具体设计须先核对当时最新 HEAD 和业务边界，不允许直接编辑 `node_modules`、移除安全校验或强制覆盖真实用户数据。

## 6. 最小验收

- 三种新卡打开/输入后，无持久草稿和正式卡 SQLite 写入；未手动保存离开，明确确认后无新记录。
- 首次主动**空白**草稿保存成功，草稿箱恰有1条；多次修改/保存更新同一条；重启读回相符。
- 完整新卡从未点草稿，直接点击发布即正式成功且从未留下持久草稿；已有草稿后直接发布则原子清稿。发布失败/未知结果旧草稿仍在。
- 错题/问答/直接记忆的星号与必填规则准确；缺项连续点击至少3次，每次中央红色提示约1秒，0次写库，内容补齐后发布成功。
- 保存/发布按钮禁用与重新解禁准确，复制粘贴/中文输入/图片/快速退出不出现缓存丢失、数据重复。
- 正式 Electron GUI 鼠标/键盘 + SQLite只读 + 新进程重启；Windows 物理剪贴板/输入法仍需 Win10/Win11 实测签核。不能用旧 `235 PASS` 为新规则背书。
