# v0.5.1 评估与调度设计

本版不更换FSRS、不声称已提高真实学习效果。目标是让输入证据更符合行测的独立方法提取，避免把答案熟悉度当成解题能力。原FSRS参数保留，暂不以小样本拟合个人参数。

1. 纯评估函数shared/assessment.ts由界面预览和后端提交共同使用；独立性、正误、方法理解、自评、效率分开记录。
2. 猜测、记得原答案、借助提示及练习不更新FSRS或原排期；独立答对但不能解释主要步骤视为方法提取失败，进入Again。
3. 答错保持Again；自评只能保守降低等级。配置目标用时且有正数计时样本时，超时最多将Easy降为Good，不能仅因慢而变成Again。未设置目标不评价效率。
4. 同日尚未到期的成功巩固不重复增长间隔；同日此前有效成功、之后新的独立失败可立即重学。已经处于失败状态时的未到期重复失败只留记录；到期短间隔重学仍正常更新。
5. 卡片集可配置默认秒数；单卡可继承、独立目标或明确不设置。单卡独立/不设置不被默认值覆盖，移动后继承目标集。设置变化不改写旧评估、旧排期和FSRS状态。
6. 每次复盘固化评估版本、目标秒数、用时、依据、方法成功与否、原始等级/效率后等级、是否更新调度及解释。旧记录字段为空，不补造评估快照、不重放旧回执。
7. 只读统计分开显示独立答案正确率、方法解释成功率、同目标且独立解对的效率、FSRS稳定性/难度/可提取率。观察比例不是能力概率。近期独立表现每个本机日历日取最后一次有效记录，最多10日；不足3日明确证据不足。此阈值是界面保守提示规则，不是统计置信区间。
8. 原mastery兼容字段保留并改称“复盘表现参考分”，不冒充FSRS可提取率。FSRS读模型随时间计算遗忘估计，读取不保存、不推进会话或排期；沿用旧规则状态时显示说明。
9. schema9迁移前保留.before-v9副本，新增两级效率配置表和assessment_snapshot；旧数据、历史和调度不改写。回收站恢复保留配置，彻底删除通过FK级联清理。完整备份覆盖新表与快照。

模块边界：评估纯函数→复盘服务资格判断→FSRS状态更新；workflow继续协调记录/回执/会话的单事务。目标策略独立服务；统计和模型估计只读。仍为模块化单体。

依据：固定依赖ts-fsrs5.4.2的实现与API。官方文档：
- https://open-spaced-repetition.github.io/ts-fsrs/ （next、get_retrievability、retention参数）
- https://github.com/open-spaced-repetition/fsrs4anki/blob/main/docs/tutorial.md （Again与Hard的语义）

行测证据资格、用时封顶和跨日展示是本项目新增产品规则，尚无真实用户长期对照实验，不作为FSRS官方保证。未实现同类题迁移能力测量、自动理解文字思路、个人参数优化或考场速度预测。
