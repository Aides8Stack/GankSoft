# S6 Knowledge Markdown v1

Use the existing dependency graph's mdast-util-from-markdown 2.1.0 as an explicit runtime dependency. CommonMark owns fenced/indented code, block quotes and HTML comment context. GankSoft recognizes only exact top-level, column-one protocol directives with a state machine; body text is sliced from original offsets rather than regenerated from generic Markdown AST. No demo parser is used.

Canonical file header: `<!-- ganksoft:md:v1 -->`. Each node is a one-line ATX heading followed by paired `<!-- ganksoft:body:start -->` and `<!-- ganksoft:body:end -->`. Body headings are ordinary content. One newline on each body boundary separates protocol from content; a serializer adds the closing separator even when body already ends in newlines, preserving original trailing blank lines. UTF-8 BOM is accepted only at the file boundary and CRLF is normalized to LF; a BOM within a node body is preserved.

An eligible literal reserved comment is encoded as `<!-- ganksoft:literal:v1:BASE64URL_UTF8 -->`. Decode exactly once inside body, reject malformed/noncanonical encoding and embedded line breaks. The serializer escapes reserved comments only in top-level CommonMark HTML nodes; fenced/indented/quoted/comment-contained text is not altered. A literal escape directive is itself escaped, ensuring a reversible representation. The serializer verifies that its output parses back to the same normalized bodies and refuses unclosed code/comment contexts or unsupported HTML blocks that would swallow structural boundaries.

Names are trimmed, nonempty, at most100 characters and contain no control characters. Names are unique under the same parent; different branches may share a name. v1 supports at most6 structural heading levels and5000 nodes. A deeper branch, missing ancestor, cycle or duplicate path is rejected with diagnostics; depth is never flattened silently. Import must preview and obtain explicit confirmation before writing. A64MiB file ceiling bounds AST input; normal IPC limits remain unchanged.

Ordinary Markdown provides heading candidates only. The caller must explicitly select heading line numbers; unselected headings remain in node bodies. Unassigned preamble or selected descendant without a selected ancestor is rejected for correction. This does not automatically reinterpret every heading as a knowledge point.

This initial parser checkpoint does not claim database import/export, image validation or Base64/width persistence. Those are the next S6 unit. Markdown files contain structure/body only; no card history or hidden node database IDs are exported. Runtime copies in Windows and Linux ASAR must include the promoted dependency, preserving the existing package and quality gates.


## S6.c media closure and shared views (2026-10-25)

The existing CommonMark AST identifies inline/reference images; code examples remain literal. Reference images are expanded to inline images and their unused binary definitions removed; an image definition shared by a normal link is rejected explicitly. Ordinary remote/file/HTML images are rejected without fetching. Data URI input must be canonical Base64 PNG/JPEG/WebP, at most20MiB per binary with the existing full native decode and40MP ceiling. No new image decoder or editor implementation is introduced.

Internal bodies contain canonical `gank-asset://assetId/placementId?width=1..100` references. `StoredNodeBody.assets` records deck-owned immutable staging metadata, safe filenames and SHA-256; absent arrays decode to empty for the existing text bodies. The additive knowledge media purpose is separate from card purposes. Each placement is unique and independent, while imported binary hashes deduplicate only inside the target deck. Deleted/merged bodies retain their resources for recovery; no garbage collector is introduced. New image files are tracked through the enclosing protocol output/receipt transaction and removed only on a definitive rollback.

Single-file exchange uses standard Markdown Data URI image destinations and the reserved image title `ganksoft-image:v1:WIDTH:BASE64URL_JSON_TITLE`. The encoded JSON value is the original string title or null. Import validates canonical extension encoding; a plain image without an extension defaults to100%. Width and original title round-trip without database IDs, absolute paths or hidden card data. Formula/color body text remains unchanged. Export copy/save reuse one prepared serialization and recheck resource integrity before use. The64MiB envelope and existing bounded renderer previews remain. Large input uses the native file/clipboard port, rather than raising IPC ceilings.

The original Mind Elixir6 public read-only/select APIs provide the exchange mount/range diagram. Import remains source→explicit heading disambiguation→read-only path/body diff→confirm. Same-path default is keep; replace/append regenerate a preview. Export options appear only after selecting nodes. The existing Crepe editor, node save controller and media adapter are reused in the outline; only one selected body loads, with the collapsible indented directory on the right. Map mode has no duplicate directory. Production startup remains604; new views are validated only through the established synthetic606 host until final production activation approval.

S5's temporary `KNOWLEDGE_MEDIA_NOT_READY` test has become a permanent `MEDIA_REFERENCE_INVALID` assertion for the same malformed/untracked URI. The rejection intent and backup/reopen assertions remain; new tests cover valid images, foreign ownership, binary corruption, placement widths, rollback and restart. Protocol media DTOs live inside shared/protocol, preserving the existing dependency boundary check.
