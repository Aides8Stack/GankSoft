## 一、右侧每行固定三部分，按层级缩进

右边导出知识点列表必须以**一个知识点占一行**的树状文档顺序呈现，随真实 parentId、position 分级缩进，不能折成扁平复选框群。每行内容：

```text
[□] 资料分析           [包含父级正文] [包含整个子树]
  [□] 增长率           [包含父级正文] [包含整个子树]
    [□] 同比增长       [包含父级正文] [包含整个子树]
    [□] 环比增长       [包含父级正文] [包含整个子树]
```

- □ 表示当前知识点的**有效选中**状态（手动勾选或因父级/子树包含条件纳入），选中行背景明显但不刺眼；内部仍须追踪直接选择与派生来源以保证取消正确。
- 后两项是**当前行独立可选的导出条件**，并非当前旧版本的两个全局开关。
- 「包含父级正文」：本节点有有效父级/祖先才可用；「包含整个子树」：本节点有后代才可用。
- 行未被选中、节点没有对应关系时，此条件以淡灰色不可点。选中行且条件有对应父/子关系时，呈浅绿色**可选态**；单击激活时文字背景变深绿色**已选态**，可再次点击取消。
- 用户没有主动勾选、但因包含父级/子树规则纳入的节点，也**必须在右侧显示已勾选并在左侧高亮**；内部不能误记为直接勾选。取消时按贡献来源保留独立选中和其他规则，导出按 ID 去重。

## 二、左右选择和滚动/定位双向同步

1. 左图谱节点单击：未选→选中；再点已选→取消。右侧同 ID 复选框即时更新，**右侧列表自动滚动居中到该行**。
2. 右侧复选框单击：左图谱同 ID 的节点选中状态立即更新，**左图谱自动定位/高亮该节点**。
3. **最新覆盖规则：右侧「包含父级正文」「包含整个子树」不只是导出参数。** 激活时，被纳入的全部祖先/后代知识点必须立即在**右侧复选框变为选中、左侧图谱同步高亮**；取消时这些节点同步取消（但明确单独勾选或由其他有效包含条件覆盖的节点仍保持选中）。条件本身加深背景。内部仍需记录“独立选中”与“由包含规则选中”的来源，以保障不误取消。
4. 右侧可以按名称/完整路径搜索，按 Enter 或点击定位按钮，左右定位，但搜索本身**不改变**节点的直接选择或条件。
5. 左右保持各自稳定滚动/缩放区域；长列表滚动不影响图谱，缩放图谱不重排右侧行。重名以 nodeId 区分，不误改。

## 二补充：包含条件的选择传播与取消规则（2026-10-30 最新优先）

用户已在实际 HTML 预览中指出：**点击或取消「包含父级正文」「包含整个子树」时，相关知识点必须真实变为选中或取消，左图谱和右列表同时变化。** 不能只让按钮变深、只改变预览正文数量而把对应节点的复选框继续留空。

1. **选中「增长率 → 包含整个子树」**：右侧「同比增长」「环比增长」及所有更深层子孙当即勾选，左侧相同 ID 全部高亮，已选计数/导出预览范围同步变化；关闭该条件，只取消**仅由此条件纳入**的子孙。
2. **选中「增长率 → 包含父级正文」**：实际有父级或祖先时，右侧「资料分析」等相应祖先节点勾选，左侧高亮。关闭后只取消**仅由此条件纳入**的祖先。
3. **保留独立选择和重叠贡献**：如果「同比增长」原本被用户单独勾选，取消「增长率 → 包含整个子树」仍应保留它；如果「资料分析」同时受到多个子节点的「包含父级」条件影响，关闭其中一项不取消另一项所需的父节点。相同 nodeId 多次贡献按集合去重，不能重复计数/导出。
4. **右侧复选框的显示由实际有效选中集合驱动**，而非仅由手动选中数组驱动。左侧图谱直接复用同一有效选中集合。内部用来源追踪（例如显式选择 Set + 各项规则贡献的 ID 集合）区分用户明确选择与批量纳入，但**用户看到的受影响节点必须全部处于真实勾选状态**，不能只用较弱的间接颜色代替。
5. **手动取消由条件纳入的单个节点**：应当真的取消这个节点。系统必须解除/部分撤销导致它被选中的包含规则，并清晰同步该规则的状态（不允许父级按钮仍显示“包含整个子树已启用”，而某个子孙却不在有效选择中）。其余原已选知识点尽量保留，不因为局部取消而误清空整个选择。具体实现可以使条件回到未启用/部分选择状态并明确处理剩余节点。
6. **选择与导出一致**：实际导出的节点和正文与左右两边的有效选择、每节点父/子规则必须一致。关闭包含条件后预览应立即失效或重新生成，不复用过时的 previewToken；点击「预览导出」得到的节点、正文数必须能解释当前两侧勾选状态。

**交互用例（必须补验）：** 子树 on → 全部后代同时勾选并图谱高亮；子树 off → 非独立后代同步取消；父级 on/off 对全部祖先对称；手动已选子孙/父级保留；两条规则重叠仅取消一条；直接取消派生节点后条件与显示一致；左图/右行二次点击同步；导出预览范围与有效选中集合一致。

## 三、协议/后端实际改动（不仅是样式）

**当前生产实现核对：**
- `src/components/KnowledgeMarkdownExchange.vue` 使用 `selected:string[]` + `parents:boolean` + `descendants:boolean`，也就是**整次导出的全局条件**。
- `src/components/KnowledgeExchangeMap.vue` 可作为只读交互基础，但需要稳定的 focus/click API 来实现两侧视图联动。
- `shared/protocol/knowledge-markdown.ts:ExportMarkdown` 当前只定义 `nodeIds`、`includeDescendants`、`includeParentBodies`；`electron/modules/knowledge-unified/markdown-exchange.ts` 按全局规则计算选择和正文。

**必须补充逐节点导出范围语义**：例如每个选中节点的 `parentBodies`/ `entireSubtree` 规则，通过显式后端协议传入，统一计算直接选择节点集合、隐式祖先标题、可选祖先正文、所选子树正文，按稳定知识点 ID 去重。若一个父级正文同时被多条路径包含，只导出一次；图片等资源继续按原有安全策略处理。不得仅把每行开关做成装饰导致导出结果不符。

保持现有 Markdown 导出预览 Token、复制、保存、大小限制、深层级标记、Schema606 数据完整性。旧请求兼容如需保留须明确版本或兼容语义，不可静默改变。
