# GankSoft v0.3.0 通用卡片集版

基于 v0.2.2 源码修改，保留 Electron、Vue、SQLite 桌面架构。本次不预设学科内容。

## 通用结构

- 卡片集有两种类型：记忆积累、错题复盘。空工作区默认创建各一个，可自由命名、新增、查找、改名、移动、排序、删除和恢复。
- 卡片集可以新增子集，子集继承父集类型。侧栏显示完整路径，选择父集时卡片列表包含子集。
- 卡片集使用稳定 ID；重命名、调整层级不修改卡片、知识点和复盘历史的关联。
- 每个卡片集有自己的知识点树，沿用新增、编辑、删除、恢复、合并、父子层级、关系连线和版本存档。
- 一张卡片属于一个卡片集，但可关联多个有效知识点；一个知识点可关联多张记忆卡或错题卡，包括跨卡片集关联。
- 删除卡片集前必须清空本集及子集中的有效卡片和知识点，防止误删整批内容。空集删除可恢复。卡片、知识点的回收站沿用“设置与数据”。

## 学习流程

记忆卡：提示 → 主动回忆 → 展开内容 → 0—4 分自评 → 保存遗忘笔记和下一次日期。可暂停、恢复排期、查看历史和继续下一张。

错题卡：保留题干、选项、正确答案、材料、解析、图片、原思路、来源、错因和改进笔记。题目依旧采用 A—D 单选模板。草稿补齐答案及知识点后可单独或批量标记为已整理。

错题库“选择卡片集 / 知识点 / 随机组题”进入组题：

1. 选择主动选题，可同时选若干卡片集，包含其子集。
2. 可叠加知识点、下级知识点和关键词条件。
3. 勾选具体题目开始，或按指定数量随机抽题。
4. 提前复盘和暂停排期的题目也可主动练习；草稿必须先整理。

“定期复盘”提供错题和记忆两种队列，分别展示到期数。错题沿用每日有效复盘预算；记忆队列可只看到期卡。主动练习同样记录学习数据。

## 间隔算法

继续使用可审计的 `rules-v1.0` 间隔规则，借鉴主动回忆和间隔重复思想，不声称实现 Anki 的 FSRS 或 SM-2。

每张卡独立保存复盘历史、评分、参考掌握分、当前间隔和下次日期。首次有效复盘按评分安排 1、2、3 或 7 天；后续随评分缩短或延长间隔，近期反复低分回到 1 天，上限可在设置调整。同日重复保存为巩固，不抬高掌握分、不延长间隔。错题借助提示不算独立验证，猜对或记住答案不会判为独立掌握。

## 批量导入与导出

兼容 `ganksoft.exchange 1.0` / `.gank.json`，不再把 subject 限定为固定学科。字段 subject 对应目标卡片集的稳定 ID；旧科目名可按兼容流程导入。

- 选择文件前指定目标卡片集，或选择文件后重新预览。记忆卡和错题卡需分别导入对应类型的卡片集。
- 指定目标后同时映射知识点存档及引用；仍展示新增、复用、冲突、待核对和排除条目。
- 重复导入同一数据包到同一个目标不会重复创建。导入不同目标有独立命名空间，不会串联两个卡片集的知识点。
- 无法确定答案或知识点的错题保留为草稿；导入后的批量整理功能保留。
- `examples/memory-template.gank.json` 和 `examples/question-template.gank.json` 可用作两种卡片的数据模板。建议明确选择目标。
- “导出整个软件 ZIP”包含 SQLite 数据库、附件、卡片集、知识点版本、导入记录、学习记录和设置；恢复支持新 ZIP 和旧 `.gankbackup`。
- ZIP 内含 `backup.json`，包含数据库校验信息；恢复前执行完整性检查，并保留恢复前的数据目录。模型 API 密钥不包含在学习备份中。
- 知识点版本仍可单独导出 `.gank.json`。完整备份恢复是整体替换，批量卡片导入是合并，两者入口独立。

## 总览与漏洞分析

学习总览保留卡片数量、知识点、到期任务、有效复盘和错题重做正确率，并展示记忆卡到期情况。

分析页支持时间范围和卡片集范围，包含各集有效复盘、答错 / 遗忘次数、高频错因、反复出错题、答对但不稳定、具体错误知识点、易忘记忆卡及证据入口。记忆自评与答题正确率分别计算。记忆卡的关联遗忘不能证明每个关联知识点都遗忘。

## 升级

1. 在旧版先导出一次完整备份，退出旧程序。
2. 解压新版，在同一 Windows 用户下运行 GankSoft.exe。保留原应用名和默认数据目录。
3. 首次打开旧库时自动升级到数据库 schema 3，并在数据目录旁保留迁移前的 SQLite 副本。
4. 旧模块转为同名卡片集，旧知识点编号、卡片编号、作答历史、导入对应和存档保留。旧政治理论 / 常识迁移记忆卡的原题记录保留为已删除记录，附件仍可读取。
5. 使用过自定义 GANKSOFT_DATA_DIR 时，继续使用原路径。

## 验证范围

- `npm test`：38 项测试，覆盖旧功能及卡片集层级、循环防护、稳定关联、指定目标重复导入、类型检查和 ZIP 恢复。
- `npm run build`：前后端类型检查及生产构建。
- `node tools/ssr-check.mjs`：使用真实 SQLite 生成测试数据，对主要页面及导航执行 Vue 服务端渲染，检查运行时模板错误。
- Windows 包沿用 v0.2.2 的 Electron Windows x64 运行时，替换本次构建的应用资源。当前环境未实机运行 Windows 程序；SSR 检查不代替 Windows 交互和视觉验收。

后续可扩展：FSRS、填空和双向记忆卡、记忆图片与音频、批量移动卡片、按卡片集导出交换包、学习会话断点继续。以上不计入本版已实现功能。


## Windows 打包修复（2026-10-15）

首个 v0.3.0 Windows 包的 GankSoft.exe 被截断为 101,777,408 字节，完整运行时文件应为 245,589,504 字节，造成 Windows 无法加载。此问题发生在运行时文件提取 / 打包阶段，不涉及学习数据库格式或功能代码。

修复包重新从原始 Windows x64 运行时提取文件，并对全部运行时文件校验长度与 CRC；发布 ZIP 再逐个与原始运行时比对 SHA-256（应用资源 app.asar 是本版构建结果，单独检查）。新增 tools/verify-windows.py，检查 ZIP CRC、必要文件、可执行架构及 PE 节边界，可识别“ZIP 自身有效但其中 EXE 不完整”的情况。

开发者校验命令：`python tools/verify-windows.py <发布包.zip> --runtime-zip <原始运行时包.zip>`。Windows 包仍未在本环境实机启动，文件完整性检查不等于实机验收。

下载修复包后请完整解压整个文件夹，再运行其中的 GankSoft.exe。请勿将 exe 单独移动到其他位置；学习数据无需清空。
