## 各阶段的循环

**核源码和 API → 最小设计 → 小范围实现 → 本地专项/真实临时数据库及相关回归 → 定向修复 → 记录验证 → 自动继续下一小阶段。**

- 优先复用第三方库原生能力和已有业务 API，模块化、低耦合。不可重做 Milkdown 内部表格/普通粘贴/图像拖拽；GankSoft 只保留资源身份、宽度、草稿与历史等最小适配。
- 严守卡片集隔离、三模式内容映射、草稿/正式发布隔离、旧复盘历史不变、图片 Asset/Placement、CAS revision/epoch、SQLite 事务/备份等。真实用户数据库与原 604 默认启动保护不受授权更动。
- 对每阶段实际有影响的功能跑专项/协议/类型/构建/必要 Electron smoke；失败先本地复现，不靠反复向 Windows CI 试错。测试不删除、skip、放宽断言或掩盖真实异常。已核实有效的无关证据直接继承。
- 将多个通过的子阶段组成适当逻辑批次提交推送原分支，必要时更频繁保存中断检查点。**提交后记录对应新 SHA 和 CI 的一次即时快照；不轮询、不等待 GitHub Actions 结束**，但不能把 CI_PENDING 说成 CI_PASS。后续恢复时优先核失败的新证据，不能忽略真正失败的必需门禁。
- 运行阶段使用既有 `NOT_STARTED/IN_PROGRESS/BLOCKED/DONE`；详细测试用 `PASS/FAIL/BLOCKED/NOT_RUN`。阶段的本地完成与远端 CI 最终认证分开记录。不要因为 pr-trust 尚未人工审批就停下功能分支开发。
