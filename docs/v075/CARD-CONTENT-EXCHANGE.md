# 三模式卡片内容交换（S7.e）

统一卡片不能无损投射到仅含 question/memory 的旧 content2.0。保留旧 JSON/gank.json/ZIP 的 reader/writer 和现有入口；新增独立的 `ganksoft.cards` version1 内容包，配套导出、校验读取、预览和原子导入。不是数据库备份/独立追加数据库功能；完整数据库历史、草稿、FSRS 与策略仍由 S8 的完整数据管理负责。

## 范围与映射

- 显式选中1–500张当前集卡片；逐卡核实身份/归属/修订，导出当前发布的一种模式，忽略未发布草稿。旧文本选项保持 `legacy-question-604`，不猜测拆分或答案。
- question-v1 保留稳定选项及正确项；qa-v1/direct-v1 使用既有 ContentPayload；无隐藏模式、学习记录、排期、单卡策略或原始历史 JSON。
- 带出当前关联的有效知识点与祖先正文。复用既有 marked Markdown + Base64 图片规则，关联指向 Markdown 前序生成的 portable key；不误用原数据库节点 ID。
- 卡片媒体按资源合并，放置和宽度独立。导入后为卡片/版本/周期/知识节点/图片资源/放置重新分配身份，内部链接同时重映射；原数据库与源集不变。
- 新建独立、可学习的卡片集；不覆盖现有卡片或合并历史。相同包重复导入默认定位先前导入的集，另导一份需用户显式勾选。先前导入集已删除时要求恢复或显式另导。

## 容器与边界

ZIP 严格包含 `cards.json` 与 `manifest.json`。Manifest 固定格式 `ganksoft.cards.container` version1，记录正文 byte size/SHA-256。复用有界安全 ZIP 容器，不按归档路径解压文件；拒绝缺项、多项、损坏 checksum、未知格式/版本。

正文/全部图片64MiB预算；每卡200个图片放置，关联500个知识点；图谱5000节点上限继承既有协议。图片字节在主进程校验，IPC只回传数量、模式和有时效token，不返回Base64/本机路径。导出前后核对epoch、数据修订和卡片修订；预览5分钟过期。

导入复用目录、图谱、媒体、关联与统一模型完整性规则。新内容版本及初始周期在同一事务建立；历史为零。Host统一负责事务输出/回执，回执写入失败整体回滚并清除本次UUID媒体文件；未知提交结果保留资源并通过原请求核对，不盲目重做。

## Typed API

- `card.exchange.preview`：选择与修订 → 只读轻量预览token。
- `card.exchange.save`：token → 原生保存对话框/ZIP；取消有明确结果，原请求重放不重开对话框。对话框结束再次校验原预览。
- `card.exchange.open`：原生选择对话框 → 校验包/轻量导入预览；取消不修改数据库。
- `card.exchange.import`：token/新名称/目标文件夹/明确另导标志 → 新deck/count/是否重复跳过；幂等回执。

`exchange-platform.ts` 是生产和隔离 Electron 共用的系统边界协调器；测试仅替换原生对话框，实际ZIP和领域服务不替换。旧交换协议、生产schema604、606隔离启用条件、发布及可信审批门禁保持既定行为。
