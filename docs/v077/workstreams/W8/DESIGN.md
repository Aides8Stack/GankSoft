# W8 — AI 调度调整离线工作流 UX 方案（仅 AI 模块）

## 0. 审查优先原则

本文件与 [CONTRACT.md](./CONTRACT.md) 和 [AUDIT.md](./AUDIT.md) 共同构成 W8 权威设计。真实嵌套为 UnifiedWorkspace.vue → UnifiedAnalytics.vue（父学习分析）→ UnifiedAiAnalysis.vue（W8 子页面）；弹窗只覆盖子页面内容区，导航栏继续可见。独立原型中的模拟左侧导航只是预览壳，不是给正式子页增加重复导航。

## 1. 需求定位与信息架构

现有 W4 已有严谨的 ZIP/Prompt/进度；现有 W5 已有来源校验、分片解析、四动作白名单、选择/prepare/apply/undo/logs。W8 **只精简交互与后台任务持有方式**。

路径：卡片集 → 学习分析 → AI 调度调整（保留既有子页面返回）。建议界面沿 OPEN-ME-v3.7 的窄图标栏和正式版网格：

- 顶部：标题、说明「离线处理，数据不会自动发送」，最近导出快照提示、后台任务入口
- 左侧/第一块：**① 导出给 AI** — 主按钮「导出分析 ZIP」，次级「高级选项」（日期仅限摘要、图片、编辑 Prompt），任务进度与完成操作
- 右侧/第二块：**② 导入 AI 建议** — 「选择 AI 返回 ZIP」，最近来源匹配结果、可执行/冲突/拒绝、建议预览与勾选
- 页面下方折叠：**调整记录** — 上次应用结果、影响范围、条件性撤销；不显示实现性协议文字
- 窄屏 900px：两块上下排列，任务提示不覆盖导航；1366/1600px 可并列。不得把左侧窄栏改成宽侧栏。

最常见的视图状态：
A. 空闲（只有两主按钮）→ B. 导出中（仍可导航）→ C. 已导出（交给外部 AI）→ D. AI ZIP 检验/来源匹配 → E. 建议预览 → F. 自动准备后一次最终确认 → G. 运行中/已应用 → H. 记录/撤销/失败。
跨页面只允许主进程任务持有导出，已准备的建议凭据仍有有效时间及数据修订约束，不因 UI 美化而长期有效。

## 2. 导出默认值

- 当前卡片集身份由学习分析上下文传入，不再让用户选一次卡片集。
- 默认保留 **全部已发布卡、关联知识点、完整学习事件、调度和历史快照**。统计摘要区间默认全部，用户修改时只影响摘要，不得暗中截断完整卡/事件。
- Prompt 沿用 W4 当前已保存版本；次级按钮「编辑给 AI 的分析说明」，原 W4 CAS 及未保存离页保护不变。
- 图片选项：首次默认不包含；用简单文字提醒「如果题目依赖图片，请在高级设置中选择包含图片；否则 AI 可能无法理解」。明确是数据私密导出，不能自动发给 AI。
- 保存位置由原生选择对话框确定，遵守系统授权；可建议记忆上次目录，不擅自绕过文件选择器。
- 文件名保持 GankSoft-v0.7.7-YYYYMMDD-ai-analysis.zip，重复名称不得覆盖已有文件；失败不显示「导出完成」。

## 3. 软件内后台任务

- 必须修复 W4 Vue onBeforeUnmount 自动 cancel 对后台行为的阻碍：持久的 Electron **主进程 jobId /状态/取消** 负责生命周期，Vue 只订阅或按活动任务查询，不持有唯一有效任务。
- 用户可在 GankSoft 打开的前提下切到卡片列表或学习页；全局轻量任务入口显示**真实的已处理卡片数、事件数、字节数和阶段**。当前 W4 ExportProgress 只有 phase/cardCount/eventCount/bytes，**无 totalCount 与百分比**：不能凭已处理数量虚构 n/N 或百分比；只有后续受信任后端提供真实总量/权重才显示百分比，且 ZIP 校验和原子改名前不得报完成。
- **百分比只在有完整工作量分母时显示**；写入结束≠100% 已完成，CRC/SHA/ZIP 展开验证成功且原子改名后才是成功。
- 取消须调用现有 export.cancel；任务进入取消/失败后清理暂存，不触发 ZIP 错误覆盖。应用退出时取消/安全清理，不承诺退出后继续。任务状态不得模拟成生产真实进度。
- 避免在所有 Vue 页面新建轮询；由唯一轻量任务适配器/主进程活动job状态持有，状态与 jobId 复用 W4。
- 既有 W4 只读固定 SQLite 快照必须保留，导出期间继续复盘不会把后来的事件插入旧 ZIP。

## 4. AI 返回 ZIP 与来源自动关联

**W5 现状**：preview.open 一次要求选择原 W4 ZIP 和 AI ZIP；原 W4 来源未持久登记，不能今天仅改 UI 就声称已自动识别。

W8 未来增加 **最小化的本机导出来源索引**（或 Electron 主进程偏好里的少量记录）：保存导出后的用户已批准路径引用、exportId、snapshotId、deckId、dataEpoch/dataRevision、文件大小/摘要及时间。**现有 ExportResult 仅返回 saved/name/cardCount/eventCount/snapshotId，没有 exportId 或完整文件路径**；必须由 Electron 已授权的保存/已核验 manifest 环节产生来源记录，不能由 Vue 猜测文件名/路径，也不能把 manifest 自校验冒充数字签名。避免保存完整 ZIP、Prompt、卡片正文或绝对私密内容到新业务表；跨库恢复后必须隔离旧来源。需查明现有设置/存储合适位置，优先复用并明确保留期限与清理行为。无需再新建 AI 学习数据库。

导入顺序：用户先选择 AI ZIP（只读拿到并严检建议 ZIP 的 source 元数据） → 用它匹配来源记录 → **重新打开并校验原始 W4 ZIP 的全部结构/manifest/hash/快照**，再比对目标库 owner/epoch/revision。任何缺失/歧义/变更，弹窗「请选择这次交给 AI 的原始分析 ZIP」；失败绝不能忽略来源验证。已导出的历史 W4 文件未记录路径时，直接采用兼容的人工补选。

W5 接口需先审查增量协议的可行性：可保持 preview.open 已有严格双文件校验内部能力，由新的来源解析器在内部完成候选绑定，或只增加一个可选 sourceSelection 入口；不能把不可信 renderer 路径当权限，不允许开放任意磁盘读路径。

## 5. 建议预览与单次高风险确认

- 展示总建议、可执行、冲突、拒绝、涉及卡片数、每行目标/调整前→调整后/原因及分页。建议仅可调 W5 当前四类动作：卡片集留存率、单卡最大间隔、知识关联卡片最大间隔、提前未到期复盘。
- **默认勾选全部合法项**，禁用冲突/拒绝项；选择量与影响卡片数即时更新（跨页选择按 actionId、规则集合计算，不只按当前页），允许用户清空。
- 点击「检查并应用」由系统自动调用 W5 现有 prepare（传已选择集合和 confirmed 的用户意图），**只读检查不另弹确认**；展示失败时哪些条件已改变。
- 只有 prepare.executable=true 才展示**一次最终确认**：操作总数、精确受影响卡片、主要调度变化和整组全有或全无提示。用户点击「确认应用」后才用 W5 apply（原 requestId/原子事务/事务内再次 CAS）。
- 预览或准备过期、学习修订变化、来源不符都禁止应用，需重新导出分析包或重新导入建议，绝不自动重放过期 AI 结果。
- 成功后提供记录和可申请撤销；复盘发生后不能保证撤销，沿用 W5 保守防护。

## 6. 数据库变化 → 强制弹窗 → 重新让 AI 生成（W8 新增强制要求）

**校验依据**：W4 分析源包的 dataEpoch、dataRevision、snapshotId/deckId、对应内容/调度指纹，与**当前实际授权 SQLite** 的状态比较；沿用 W5 来源及目标校验和最终事务中的 CAS。不依赖文件名，也不把页面刷新/只读查询/单纯导出进度算作数据库修改。发生正式学习、卡片编辑发布、知识关联变化、策略或排期修改、恢复/替换数据库等实际业务变更时，凡是 W5 认定源修订或身份不再一致，均按旧建议失效处理；无论变化是否来自另一页面，都不继续使用旧来源快照。保存 Prompt 不必凭 UI 假设数据修订变化，以真实 W5 修订/指纹为准。

**触发点**（至少三个）：① 选择 AI 返回 ZIP 后，对比源快照与当前库；② 建议预览/准备期间收到 dataSync 更新（含切换页面后回到此页）；③ 点击「检查并应用」前、最终确认后事务提交前重新验证。若导出过程中复盘导致固定快照完成时已落后当前库，最新分析导出任务完成后也应将此来源标为“需重新导出”，不要悄悄推荐过时 ZIP。必须以服务端事务检查为最终权威，UI 弹窗不能代替后台拒绝。

**表现**：弹窗标题「学习数据库已经更新」，正文「当前 AI 建议来自旧学习数据，不能继续应用。请重新导出最新学习数据，交给外部 AI 重新分析，再导入新的建议 ZIP。」主要操作「重新导出最新分析 ZIP」，次操作「暂不处理」。仅遮罩当前 AI 工作区，不覆盖全局窄图标栏/主导航。弹窗不可在同一失效事件中无限重复叠加；需要可用键盘操作与正确焦点恢复。

**状态**：出现弹窗时立即撤销尚未消费的 prepared 凭据、关闭执行确认、阻断 apply/旧请求重放、将旧预览标记 stale。点击「暂不处理」仅关闭弹窗，旧建议仍不可选/不可执行；不删除原数据或历史。点击「重新导出」启动新的 W4 本机导出（由用户选择保存位置），旧 AI 建议**不能在新导出后自动变有效**，必须等待外部 AI 针对新 ZIP 生成并重新导入**新的**返回 ZIP；新分析文件不自动上传。旧 pending operation 若提交状态未知，必须先核对原 requestId 再决定是否可重新导出/应用，不能隐瞒已提交操作。自身 W5 成功提交导致的 revision 增加不应误触旧源失效弹窗影响已成功的回执展示。

**实现上的事件状态机**：VALID_PREVIEW → DB_CHANGED → STALE_BLOCKED + STALE_DIALOG_OPEN → (DISMISS → STALE_BLOCKED | REEXPORT → WAIT_NEW_AI_ZIP) → NEW_AI_ZIP_SELECTED → REVALIDATED_PREVIEW。若旧源再次被选择，保持失效，不能自行解除拦截。每次新包导入都重新进行全部 W5 安全校验，且真正写入前仍做事务内二次/三次验证。

## 7. 错误提示和微文案

| 情况 | 推荐短反馈 |
|---|---|
| 未导出 | 「先导出完整学习数据，交给 AI 后再导入返回包。」 |
| 导出中 | 「后台导出中，你可以继续使用 GankSoft。」 |
| 包已完成 | 「文件已生成。软件不会自动发送给 AI。」 |
| 缺原始来源 | 「没有找到对应的原始分析包，请补选本次交给 AI 的 ZIP。」 |
| 源失效 | 「学习数据已经变化，请重新导出并让 AI 分析最新数据。」 |
| 部分冲突 | 「有冲突的建议已排除，可查看原因。」 |
| 准备校验失败 | 「当前调度已变化，本次建议没有执行。」 |
| 未知回执 | 「正在核对上一次操作，请不要再次应用。」 |
| 不可撤销 | 「应用后已有新的学习变化，为保护记录，无法撤销本组调整。」 |
| 取消导出 | 「正在取消并清理临时文件…」 |

## 8. 再分析的精确锁定条件

重新导出仅生成新的 W4 ZIP，不会自动刷新旧 AI 建议的来源标识。旧 ZIP 即使再次被选择也继续拒绝；只有外部 AI 基于**新 exportId/snapshotId/epoch/revision**生成的新建议 ZIP 严格校验成功，才可进入新预览。导出过程中新的复盘使刚生成的固定快照过期时，显示“文件已生成，但相对当前学习数据已失效”，而不是让用户误以为它可直接用于调度。遇到 unknown 写回执时先查原 requestId，不能简单说“未执行”。

## 9. 边界

离线 AI 协作，而不是实时 AI 分析引擎。W4导出的 ZIP 保持现有 ganksoft.ai-analysis/1、Schema606；W5只接受 ganksoft.ai-schedule-actions/1 白名单动作 ZIP。优化不改变旧记录、FSRS 核心、学习计划、卡片正文、知识图谱结构或资源预算。

原始包与 AI 包的来源配对必须有严格验证，不能从用户肉眼相似的文件名猜测。普通内容 ZIP #36、数据库备份、卡片集迁移均不属于 W8。
