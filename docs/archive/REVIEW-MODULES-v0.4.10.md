# v0.4.10 卡片集调度、自评分和单卡统计

## 使用入口

1. 左侧打开任意卡片集，在第二侧栏点击「复盘调度设置」。配置仅作用于本卡片集。
2. 复盘时点击「调整本卡调度」。用弹窗调整本卡最大间隔，关闭后继续当前作答，答案和思路保留。
3. 错题作答并展开解析后，拖动「本次自评分」滑块。答对范围 6.0—10.0，答错范围 0.0—5.9，步进 0.1。可用方向键调整、Home/End 选择边界。
4. 在题目项目页或复盘中点击「查看复盘数据与变化」，查看本题数据。记忆卡详情和复盘中也提供同一数据入口。

## 两层调度配置

| 配置 | 范围 | 规则 |
| --- | --- | --- |
| 卡片集每日到期任务上限 | 1—200 | 自动到期队列按本集当天有效复盘数扣减；手动选择卡片可继续学习 |
| 卡片集默认最大间隔 | 1—365 天 | 只影响本集沿用默认值的卡片，各卡片集独立 |
| 单卡最大间隔 | null 或 1—365 天 | null 继承所属集；独立设置覆盖卡片集默认值 |

调小上限会提前超过上限的现有计划，并同步 FSRS 内部 due；调大上限不会推迟已有较早任务。修改不增加复盘次数，不改历史事件、掌握参考和暂停状态。卡片移动时，独立设置随卡片保留；没有覆盖时使用目标集默认值并提前过长计划。编辑页面移动、批量移动采用同一调度策略模块。

已有全局设置只作为升级迁移输入：迁移时将其复制为每个已有卡片集的初始配置，并保留单卡覆盖。新建卡片集初始每日上限为 15、最大间隔为 60 天，可分别调整。设置页不再提供跨所有卡片集的调度写入入口；旧 settings.save 命令会拒绝并提示进入指定卡片集。

## 自评分与调度

自评分不是客观正确率，也不是掌握概率。原 `attempts.score` 继续表示 0—4 调度等级，新增 `attempts.self_score` 表示原始 0—10 用户评分，两者不互相覆盖。

| 客观结果和自评 | 自评对应等级 |
| --- | --- |
| 错误，0.0—2.9 | 0（重来，较低表现） |
| 错误，3.0—5.9 | 1（重来） |
| 正确，6.0—6.9 | 2（困难） |
| 正确，7.0—8.9 | 3（正常） |
| 正确，9.0—10.0 | 4（轻松） |

先按客观正误、作答依据和方法理解计算原调度等级，再与自评对应等级取较低值。因此猜测或记得答案不能仅凭高自评进入独立熟练状态；提示学习不改变正式排期。等级 0、1 都进入 FSRS 的 Again 路径，但掌握参考保留表现差异。FSRS 结合历史难度、稳定度等估算下次时间，最后应用本卡有效最大间隔。

滑块初始值：答对 6.0，答错 3.0。用户可按真实表现调整后提交。自评分、反思随草稿保存；请求待确认时锁定输入，原请求编号重试不重复创建记录。

新协议 v2 的错题请求必须携带 self_score。v1 和升级前已保存的待确认请求保留兼容性；其缺失评分为 null，统计时显示未记录。前后端共用评分函数，后端校验正误分段、有限数值和小数步进；数据库额外约束范围及其与客观正误的一致性。

## 单卡统计口径

- 总次数包含已保存的全部记录；有效复盘与练习／同日巩固分别计数。
- 默认选择当前内容版本。新版题干尚无复盘时显示无记录，可切回旧版本；不会把改题前后走势连在一起。
- 正确率、平均自评和变化只使用所选范围的有效复盘；均分只包含实际填写自评分的记录。
- 自评变化比较同一内容版本最近两条有自评分的有效记录。练习及缺失评分不参与变化计算。
- 全部版本用于历史总览，可看明细和整体统计，但不绘制跨版本自评连线、不给出跨版本变化值。
- 走势按有效复盘的先后顺序显示，非等时间间隔；缺失评分留空，不人为插值。每个点可查看次序、时间和自评分。
- 每条明细保留本次答案／正误、自评分、调度等级、用时、当时排期／上限、掌握参考、原始思路、具体错因、知识漏洞和反思。
- 明细的排期取当次调度事件快照。之后修改设置不会改写当时安排；练习记录显示保持原排期。早期没有事件或字段的记录保持未记录。
- 记忆卡没有客观答案判定，保留原有四档回忆自评；数据窗口不伪造十分制均分和客观正确率。

## 模块与协议

| 模块 | 职责 | 通信 |
| --- | --- | --- |
| shared/review-contract.ts | 卡片类型、配置 DTO、复盘请求与结果 | SaveReviewPolicyCommand、DeckReviewPolicy、QuestionReviewCommand |
| shared/self-assessment.ts | 自评分校验、客观评分、自评合并 | UI 和后端共用纯函数 |
| review/policy.ts | 两层配置解析、保存、提前现有计划 | deck.reviewPolicy.save、card.reviewPolicy.save、effectiveMaxInterval |
| review/workflow.ts | 幂等请求、记录与会话原子提交 | SessionPort；支持协议 v1、v2 |
| review/service.ts、memory/service.ts | 写入各类复盘记录 | 调用策略模块和 FSRS，不依赖 UI |
| review/fsrs.ts | 计算并保存排期与历史事件 | 接收综合调度等级，统一解析上限 |
| review/analytics.ts | 单卡统计只读模型 | card.reviewStats；不写计划、历史、会话或回执 |
| DeckReviewSettings.vue | 卡片集配置视图 | 调用配置命令 |
| CardReviewPolicy.vue | 复用单卡配置界面 | 详情页与复盘弹窗共用 |
| SelfAssessmentSlider.vue | 自评分滑块 | v-model，不访问数据库 |
| CardReviewAnalytics.vue | 单卡统计窗口 | 调用只读模型，处理加载／重试／空数据和版本筛选 |
| useStudySession.ts | 作答阶段、草稿、提交与重试 | 复用共用评分函数，提交 self_score |

Application 是命令和事务边界；配置、历史、调度和统计通过显式服务函数与 DTO 连接。新统计查询不依赖作答状态机，不会因为查看统计改变学习状态。
