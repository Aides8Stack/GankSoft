# v3.7 原版左侧导航恢复 — 用户最终决定（2026-10-27）

## 问题与决策（强制）
原型 `docs/v075/reference/OPEN-ME-v3.7.html` 的最左侧是**完整卡片集导航目录**，不是一排功能小图标。开发包此前错误宣称“用户要求默认左侧68px窄图标栏”，造成 P0–P3 正式 Electron 截图与原型严重不同。用户明确纠正：**原型主布局一模一样；可以补齐原型缺失的业务 UI，但不能删掉或改变左侧目录**。

本条是对冲突的旧叙述的显式撤销，不要再将它解释为“可收起的纯图标栏默认模式”或“在目录旁额外加一根图标列”。只按冻结的原型 CSS/DOM 原样实现；不做新导航方案。

## 原版 HTML 直接查证
- `.app-shell`：主导航+工作区并排。
- `.left-rail`：原型 CSS 的 `width:213px; min-width:213px`（使用原型真实响应式断点，而不是随意改为 68px）。
- `.brand`：GankSoft 标识和“知识 · 记忆 · 复盘”副标题。
- `.rail-link`：**学习总览**。
- `.rail-head` / `.deck-group-label` / `.deck-link`：**卡片集**标题、新建/管理入口、文件夹分组、各卡片集的名称、数量、颜色/选中态及交互。
- `.rail-bottom`：设置、版本/状态等原型底部区。
- `.topbar`：面包屑/当前卡片集和页面定位。
- `.subnav`：进入卡片集后的概览、所有卡片、筛选学习、复盘、知识图谱、学习分析、导入导出、调度设置等可见二级导航。

实际实现不可把 `.left-rail` 的这些内容转移到图标的 tooltip 或空白主页。原型 CSS、配色、间距、品牌尺寸、行高和列宽按原文件同屏还原；如果业务中有真实文件夹/卡片集，多数据项使用真实 `workspace.catalog` 递归或分页 UI，不能显示静态演示名单。
