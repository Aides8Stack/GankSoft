## 概要

已具备 FSRS-6（ts-fsrs 5.4.2）、单卡及卡片集最大间隔、多维评估、事务保存、幂等回执、错因与知识点标记、回顾时间线和分析。薄弱之处不是“没有间隔记忆”，而是优先级规则与错因/题型/知识弱点分析未连接；历史分析又缺少内容版本隔离、近期改善和覆盖率校正。

## 源码发现（观察与设计建议分开）

### P1 — 优先队列仅依据失败次数和逾期天数，且权重失衡（已确认）
- `src/store.ts:20-51`：最近三条 `effective` 记录中，`score<=1` 每条 +100，逾期天数最多 +30；队列只考虑已到期题，排序后由 `src/App.vue:224-257` 切片。
- 情境：题 A 最近两次失败、逾期一天约 201 分；题 B 没有这类失败、逾期 120 天最多 30 分。B 长期可能被挤出每日队列。
- 现有排序不读 `faults`、知识薄弱程度、答案正确但方法失败、同类型题多次错误、证据置信度，且不能解释排序依据。
- 建议：独立 `shared/review-priority.ts`（纯函数）和服务端队列读模型；先过滤资格与状态，再在到期任务里按逾期公平性、当前版本失败、方法失败、重复错因、知识难点和近期趋势排序。逾期保障与薄弱题配额分层，不用无限制线性分数取代 FSRS。返回可解释的 `reasonCodes`。

### P1 — 优先级与反复错误筛选没有隔离卡片内容版本（已确认）
- `electron/modules/questions/content.ts:3-17`：编辑内容时增加 `content_version` 并清空该题 FSRS 状态，新的计划立即待验证；旧复盘快照保留。
- 然而 `src/store.ts:20-33` 的 `recentAttempts` 不筛 `content_version`；`src/components/CardExplorer.vue:81-137` 中 `last-failed`、`repeated` 也没有按现行版本区分；`electron/modules/analytics/deck.ts:52-61` 的三次有效作答分析按时间段而非版本；`electron/modules/analytics/window.ts:80-88` 易错卡在所选窗口内累计失败，不考虑新版本已改善。
- 影响：修订题干/答案后，旧内容的失败会继续影响“优先复习”“最近失败”“易错榜”，与 FSRS 已重置的语义不一致。
- 建议：默认仅用当前 `content_version` 计算即时风险、当前弱点；历史版本单独做“全部历史”时间线展示；卡片修订后前端显示“当前内容证据不足”。

### P1 — 手动延期与 FSRS 内部到期可能不一致（已确认的代码路径，UI 触发范围有限）
- `electron/modules/questions/service.ts:187-205`：`plan.set` 的 `tomorrow` 分支仅更改 `plans.due_at`。
- `electron/modules/review/fsrs.ts:5-8`：`schedulingDue()` 使用 `scheduling.data.due`；`electron/modules/review/service.ts:68-81` 据此判断同日作答是否有效。
- 因而经此 API 手动延后后，到期队列用 `plans.due_at`，但同日后续复盘是否推进排期用另一时钟。当前主界面搜索到的 `plan.set` 调用主要为暂停/恢复，未发现可见的“明天复习”按钮；故属于真实后端一致性隐患，不应称为目前 UI 必然暴露的缺陷。
- 建议：选择单一权威到期日，或把人工延期作为独立覆盖层 `manualSnoozeUntil`，所有资格判断统一应用；不可把手动延期伪装成成功复盘，不应篡改 FSRS 历史事件。对延期后同日提交增加集成测试。

### P1 — 每日上限消耗的是有效复盘次数，而非去重卡片数（已确认）
- `src/App.vue:229-256`、`src/composables/useStudySession.ts:38-59`：`today` 对同卡片的每条 `effective` 记录计数。
- `electron/modules/review/service.ts:65-88`：新题、跨日、FSRS 当天再次到期或同日退步可再次有效；这具有合理的再学习语义，却会重复消耗“每日到期任务上限”。
- 建议：明确区分每日 *新领取任务的卡片数*、*总有效复习次数*、*同日重学次数*；每日上限限制新进入队列的卡片，必要重学单列预算。改变语义前须兼容旧统计并验证不会饿死新卡。

### P2 — 错因分析与排期脱节（已确认）
- `shared/types.ts:12-21` 设有八类错因；`electron/modules/review/service.ts:130-167` 按次保存到 `attempt_faults`，并可标记具体知识点。
- `electron/modules/analytics/deck.ts:39-112` 与 `window.ts:73-132` 能出错因频率、错点、易错卡榜，但 `src/store.ts:44-51` 的队列未使用这些特征。
- 建议：额外引入只读“诊断层”，按错因建议不同的复习方法：知识缺失先回知识卡；审题错误做条件定位；推理或计算错误做相似题；时间问题做计时训练；操作失误做检查清单。不要不加区分地把所有错因转换为 FSRS 遗忘评分。

### P2 — 题型维度不足（已确认）
- `electron/infrastructure/schema.ts` 中 `questions` 具有 `module` 与 `question_knowledge` 关系，无专门的规范化 `question_type` 字段；`decks.kind` 只区分 question/memory。已有关联知识点可表达部分题型，但结构化类型没有被统一的风险分析使用。
- 建议：优先明确知识树中的“题型节点”及稳定标识，避免重复分类。若一个题同时归属多种题型，再通过可选的多对多 `question_type` 关联扩展；导入协议和历史卡必须可缺省，不能强制迁移或删除用户数据。

### P2 — 易错统计缺少近期变化、样本量和选题入口（已确认）
- `electron/modules/analytics/window.ts:80-88` 统计选择窗口内的失败总数；`electron/modules/analytics/deck.ts:52-61` 采用三次有效作答中至少两次错误的简单规则。
- 缺少“最近 7/30 天 vs 历史”“连续改进”“按关联题数归一化”“跨日独立证据天数不足”的统一读模型；用次数排名更可能突出复习次数高的题，而不全是未掌握题。
- 建议：知识点风险提供分子、分母、最近趋势与置信度；区别未接触、证据不足、持续薄弱、显著改善。分析卡片可一键以此知识点创建专项复习队列，并保留用户能调整数量、日期区间与随机抽题的入口。

### P2 — 保留了不可达旧复盘组件（已确认）
- `src/components/ReviewHub.vue` 引用 `ReviewWorkspace.vue`，但 `src/App.vue:829-832` 使用 `StudyWorkspace.vue`；搜索未发现其它对 `ReviewHub.vue` 的挂载。
- 旧 `ReviewWorkspace.vue:42-47,87-95` 仍引用全局 `settings.dailyLimit`，与当前每卡片集上限不同。属于维护和测试口径风险，不应当作实际 UI 的当前问题。
- 建议：确认不被外部入口引用后，将旧实现归档或删除，确保没有丢失特有功能，所有后续队列逻辑统一到现行入口。

### P3 — 时间边界与观察刷新（已确认低优先级）
- `src/store.ts` 通过 `Date.now()` 计算到期；`src/App.vue:615-620` 每 60 秒主动 `refresh`，因此一般仅有最多约一分钟的刷新时差，不属于严重的“不刷新”故障。
- 建议：未来由单个可测试的 `now` 读模型计算过期，统一研究学习时区、睡眠跨日、系统时钟变化，避免性能优化时误删定时刷新。

## 目标架构（不重写既有系统）

1. `review/fsrs.ts`：只管理记忆状态和原始到期时间；维持现有结果、事件日志与内容版本重置。
2. `review/service.ts`：写入单次作答、评估资格、事务和回执；保持原有模块边界。
3. 新增只读 `review-risk.ts`：从当前版本的有效与无效记录、错因、知识点、计时、历史跨度生成风险特征和可解释理由；不得修改 FSRS。
4. 新增纯函数 `review-priority.ts`：在“到期/初学/专项/同日重学”资格桶内排序；逾期公平性保底，防止反复失败题霸榜；风险的相对权重可配置并有稳定 tie-breaker。
5. 新增 `review-queue` 服务：根据卡片集、日期区间、知识点、题型、错因、计划暂停、今日预算生成原子快照，避免多个前端入口重复计算。应当先与现有 API 契约设计对齐，API 版本变化要显式更新协议与测试。
6. 新增 `knowledge-risk` 读模型：知识点归一化错误率、跨日独立证据、最近走势、题型覆盖率，输出诊断并支持一键专项复习。
7. UI：今日复习分为“优先到期 / 重学纠偏 / 专项突破 / 自由抽题”；显示排期原因、主要错因、所属知识点、近期趋势、预计题量、完成进度。手动复习默认保留练习模式，不应悄然推进 FSRS。

## 首批实施顺序及验收

**第一阶段：低风险修复**
- 统一到期资格和手动延期语义；内容版本隔离；每日预算采用明确的唯一卡片语义；代码注释与 UI 用词一致；增加纯函数和集成回归测试。
- 验收：编辑题目后旧失败不参与当前排序，但历史仍可查看；手动延期、暂停、提前练习、同日重学不出现两个不一致的到期判断；不同卡片集预算隔离；幂等提交不会消耗两次预算。

**第二阶段：独立风险引擎**
- 保留原 FSRS 结果；基于当前内容版本与近期跨日证据排序，出具 `reasonCodes`；实现逾期兜底、首次复习覆盖与疲劳/重复惩罚。
- 验收：两次近期失败不会永久压过严重逾期题；成功改进可让风险下降；同一个快照、固定时钟和排序参数得到相同队列；错因缺失、知识未关联和旧版记录均可处理。

**第三阶段：专项复习与分析**
- 统一题型/知识点/错因维度，支持按原因与时间筛选、一键选题、随机抽题、跨日趋势、覆盖率和诊断建议。
- 验收：复盘记录与计划写入保持独立；历史版本和卡片集不串数据；错因、知识标签不会篡改原始答案或评分；后台预览不会改变学习记录。
