# 知识图谱 — Markdown 大纲完整阅读与单树工具栏精简

> **状态：待实现。** 来源：[#25](https://github.com/Aides8Stack/GankSoft/issues/25)、[#26](https://github.com/Aides8Stack/GankSoft/issues/26)。
> 以 `OPEN-ME-v3.7.html` 所确认的紧凑应用布局为基准，左侧窄栏与卡片集区域不改成传统宽侧栏。

## 1. Markdown 大纲：进入后每个知识点正文都默认展开

- 进入「知识图谱 → Markdown 大纲」，**所有已载入知识点**以真实父子层级连续排列，知识点标题下立即显示**完整 Markdown 正文**。未选中的其他知识点也必须全文显示；不是只显示标题/一行摘要/最多160字符。
- 全文阅读为**一个纵向滚动文档**；正文长短自然撑开，不裁切；列表、链接、图片、公式、表格、代码块与原有换行都应正确显示。图片或大表可局部横向滚动，正文不能整段截断。
- 当前选中的一个节点可编辑，其他节点只读**全量渲染**；切换编辑目标时其他节点仍保持展开，不为所有知识点一次性创建重型富文本编辑器。
- 可手动折叠节点正文和选择“全部展开/全部收起”；**首次进入默认全部展开**，用户在本次阅读会话显式折叠的状态可保留。全部展开不仅影响导图节点结构，还应展开大纲正文。
- 右侧目录的节点层级、定位/滚动与选中准确；空正文要明确“暂无正文”，加载错误不能假装空白。分层/分页加载时提供加载完整内容路径，不能让摘要充当未加载正文。
- 100+节点时可用只读增量/懒加载，但滚动到每个节点必须最终看到完整正文；保持流畅、避免卡顿或丢失未保存编辑器输入。
- 已定位当前实现：`src/components/KnowledgeOutlineDocument.vue` 的 `openBodies` 默认空 Set、`isOpen` 仅让选中项展开；`src/components/KnowledgeNodeSummary.vue` 会截取160字摘要；`src/components/MindMapWorkspace.vue` 接入大纲。

## 2. 思维导图是单树：删除额外一级新增入口

- 用户最终明确：**“我们是单树，没有一级节点，可以删除这个。”**
- 页眉右上 **「+ 一级知识点」必须删除**，浮动工具及更多菜单内的 **「新增一级知识点」入口也不得保留**，不能换个位置继续出现。
- 用户的常用新增功能是**给选中节点新增子节点**、**在选中节点旁新增同级节点**；两者都有明确且**唯一的主要工具栏入口**。不添加“建立第二棵根树”的能力。
- **只删冗余 UI 操作入口，不删除任何已有一级/顶层知识点，不改既有 ID、parentId、正文或 Schema606。** 因历史数据或空树可能存在的结构边界，需要先确认“从空树首次建节点”的可达性；若底层存储模型与用户单树展示有差异，保留兼容、报告风险，不能悄悄迁移/清空。
- 不要把当前截图里的“8个一级知识点”误解为授权删除8个知识点；这是旧 UI 的统计显示，不是用户要求删除数据。

## 3. 顶部空间和工具栏整理

### 上方压缩

1. 顶栏面包屑、二级导航已经展示「知识图谱」，因此**删除内容区重复的大标题「知识图谱」**。
2. 统计保留一行**小字号、低权重**文本，例如“记忆积累 · 17个知识点”；不必突出“X个一级节点”，不单独占据大行标题。
3. 删除独立「+ 一级知识点」；压缩页眉 padding/留白、过高工具栏和无关常驻消息横条。主画布应得到明显更多高度。
4. 默认缩放应基于实际可用画布进行合适适配；不要因为节点数量多，就把所有节点缩到无法阅读的极小字体。保留缩放、回中心、适应视口及全屏行为。

### 功能分组与纯图标（重要：**禁止常驻文字标签**）

- 主工具栏优先一行、紧凑纯图标、间隔清晰。按 **缩放/定位｜布局/展开｜撤销/重做｜新增节点｜搜索/知识栏｜导入/导出/更多** 分组，避免功能全部堆在一组里。较窄窗口可用溢出菜单，不让工具栏无限换行挤压画布。
- **“新增子节点”“新增同级节点”绝不能在图标旁加简短文字。** 采用可明确体现**父→子分叉**与**同层平行**的两种不同图标；悬停提示/`title`/`aria-label`/键盘焦点提示可保留中文功能名称。不能用两个难区分的普通“+”。
- “新增下级/同级”各只有一个主要入口；底部/浮动区重复的新增、上移/下移、展开/收起、保存需去重/整合。上下文右键快捷操作可以保留，但不得制造多余根节点新增入口。
- “同级上移/下移”等低频动作放入合理的“更多”分组，**不占据主工具栏多个重复位置**。
- Markdown 导入/导出应有**清楚、可发现的纯图标入口**，摆在工具栏右侧并与普通节点操作分组；不能删除现有导入预览、事务和导出完整内容功能。
- 图标在暗/亮模式和 900 / 1366 / 1600px 宽度下均可辨认、可点、有 tooltip；不能因强行缩小命中区域而影响操作。

- `src/unified/v37/pages/knowledge.css`：`.page-heading`、`.r5-mapbar`、`.r5-map-footer` 保留较多高度；需检查最终生效的后置 CSS 覆盖。

## 4. 最小验收矩阵

- 用原有17节点的多层树截图对照，检查**画布可用高度增大**、节点在可读比例显示、工具栏单行；核对所有节点 ID/父子关系/正文未改变。
- 900、1366、1600px 三宽：子节点与同级节点图标明显区分、没有常驻文字、tooltip/aria 正确、搜索/布局/缩放/导入导出菜单不会溢出屏幕，点击命中稳定。
- 只选已有节点新增子节点、同级节点；不能从任何位置创建新“一级根树”；撤销重做、同级上移下移、删除知识子树、回收恢复、导入导出仍可使用。
- 单树空数据的首个知识点可达性与旧顶层节点兼容性要专门验证，不得为删除 UI 入口牺牲基本建树能力。
- 进入 Markdown 大纲，不点击任何知识点即可滚动阅读全部正文（包含超过160字内容、图片、表格、公式）；切换编辑节点其他正文不自动折叠；100+节点性能可接受。
- 正式 Electron GUI 操作与必要数据读回为主，Windows10/11 物理试用独立标记；不重跑全250条历史测试。
