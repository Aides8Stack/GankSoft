# GankSoft v0.4.8：复盘可靠性测试设计与功能审计

## 目标与范围

验收目标：同一道题连续复盘三次，答案、原始思路、具体错因、知识漏洞和反思分别留档；相同提交重试不重复；退出后草稿可续写；题目修改不混淆历史；真实重启、完整备份恢复后记录、会话与排期一致。

本次以 v0.4.7 为基线，先编写失败用例，再修复并运行回归。所有验证使用独立临时数据目录，不操作用户实际学习数据。

## 已修复的审计问题

1. 具体错因从分类附属记录提升为复盘独立字段，分类为空不再丢失文字；历史页提供完整描述。
2. 新复盘保存不可变题目快照和知识点名称快照；历史题图通过历史记录读取，移除当前题图不覆盖旧图。
3. 使用独立的内容版本保护作答上下文，避免把旧草稿按新题目版本提交；核心内容变化保留暂停排期设置。
4. 新增请求回执。记录、FSRS事件、回执、会话已保存状态在同一数据库事务中提交。
5. 草稿写入串行化并校验会话修订号；重复相同保存不再反复递增版本，避免卸载组件时的保存竞争。
6. 新增本机临时草稿兜底、保存状态、保存失败重试；响应不明确时锁定原提交内容并沿原编号重试。
7. 明确区分后端拒绝与传输结果未知：前者允许修正输入；后者先确认原提交，避免重复创建记录。
8. 已有会话需明确选择继续或重开；题目版本冲突会保留旧思路作为草稿，不伪装成有效复盘。
9. 手动录入必须提供有效正确答案；旧版缺答案卡片仍可编辑，避免进入可学习队列，不恢复“待整理”状态。
10. v2备份增加附件校验，并以临时文件写入、完成后替换。恢复后清理本机临时草稿，避免覆盖已恢复数据。
11. 卡片集内容包补充长期项目笔记；更新已有笔记时显示差异并遵循导入更新策略。
12. 修正“操作已经提交但刷新失败”被误报为提交失败的反馈；取消备份/恢复不再显示成功提示。

## 逐步模块化与通信边界

| 边界 | 实现 |
|---|---|
| 渲染进程到主进程 | IPC请求，统一的 CommandResponse 成功/拒绝结构；传输异常单独处理 |
| 共享契约 | shared/review-contract.ts：协议版本、作答命令、结果和会话端口 |
| 页面到学习状态 | src/composables/useStudySession.ts 管理草稿、阶段、重试和反馈，StudyWorkspace负责呈现 |
| 复盘协调 | electron/modules/review/workflow.ts 处理幂等回执，通过 SessionPort 调用会话模块 |
| 会话模块 | electron/modules/sessions/service.ts 校验队列、修订号、阶段和原稿冻结，记录提交结果 |
| 卡片内容 | electron/modules/questions/content.ts 统一内容变更失效和历史内容快照 |
| 调度 | 现有FSRS模块继续提供计算接口，不把调度计算写入页面 |
| 数据事务 | Application在一次事务中协调上述模块；不使用异步消息把关键写入拆成多个最终一致操作 |

本次是模块化单体的渐进改造。其他已有模块仍保留兼容接口；不宣称全软件已经消除any或完成全部协议迁移。旧调用未传请求编号时仅用于兼容，新的桌面学习流程始终传稳定编号和内容版本。

## 数据兼容与明确边界

- 数据库由schema 4升级到5，升级前保留数据库副本。旧版软件不能直接打开schema 5，升级前仍建议导出完整备份。
- 旧历史中原本没有的题干/选项快照无法准确补造；显示“旧记录，无完整快照”。旧版已经丢失的文字也不会被虚构恢复。
- 旧版草稿未绑定内容版本时要求重新验证，并保留原草稿供参考。
- 支持旧v1备份；旧备份未包含附件哈希，无法补充追溯其当时完整性。新v2备份具有逐附件校验。
- 卡片集内容分享包不等于完整学习迁移包；完整数据库、历史、排期和会话使用完整ZIP备份。
- 本轮覆盖正常退出、真实应用重启、明确的数据库失败和提交后响应丢失；不将其等同于任意断电、磁盘硬件损坏保证。
- Windows包做运行文件、PE和ZIP完整性校验；桌面交互测试运行于Linux Electron，未进行Windows 11实机验收。
- 大规模分页、全软件DTO迁移、更多字段级错误码、通用编辑器离开保护、知识漏洞闭环和系统级到期通知仍属于后续工作。
