# W7 业务与技术设计

## 1. 核心模型
复盘队列是会话进度容器，不是卡片所有权锁。学习记录以单张卡片的有效评分提交为原子单位。FSRS只由系统正式调度复习路径推进。

### 学习模式
- `practice`：用户主动选择的自主练习。保存学习事件、评分、客观结果、耗时、反思和知识点快照；不写 schedule_events，不调用 advanceSchedule，不改变 scheduling。
- `scheduled`：系统到期/Again重学。保存学习事件，并在同一 SQLite 事务内写 schedule_events、更新 scheduling。

模式在创建会话时确定并持久化，提交时以服务端存储的会话模式为准，客户端不得覆盖。

## 2. 正式队列唯一性
唯一范围为 `deck_id`。每个卡片集最多一个未完成 scheduled 会话。创建、查找或恢复必须在事务中完成，避免并发双创建。已有活动正式队列时，概览入口恢复其 sessionId；队列完成后下一次启动重新读取最新 due/relearn 卡片。

due 与 relearn 是正式队列内部的来源分类，不是两个队列。队列创建时固定 cardIds 顺序；队列期间新到期卡片进入下一轮，不动态插入当前队列。

## 3. 自主队列
practice 会话不参与正式队列唯一性检查。每次独立主动启动创建新 sessionId。相同 requestId 重试返回同一结果；新的用户动作产生新 requestId。不同自主队列可包含相同 cardId。队列内部仍禁止重复 cardId。

## 4. 逐卡持久化
每张卡的评分提交独立事务：
- practice：learning_review_events + 会话当前卡结果/进度。
- scheduled：learning_review_events + schedule_events + scheduling + 会话当前卡结果/进度。
任一张卡失败只回滚该卡本次事务，不回滚之前已提交卡片。eventId/requestId 幂等。队列完成仅更新会话归档状态，不触发批量学习记录写入。

## 5. 内容修改与调度隔离
内容版本、题目类型内容、媒体、Markdown、答案、解析及知识点关联的变更不调用 FSRS，不修改 scheduling、cycleId、正式复习次数或 dueAt。活动会话继续使用创建时冻结的内容版本；提交事件绑定该 versionId。新会话读取最新发布版本。明确的调度设置/AI调度调整不属于内容编辑。

## 6. AI分析数据
W4 导出所有 learning_review_events，关联各事件当时的 contentVersion；practice 事件没有 schedule_event 时必须正常导出 null，不得丢弃。未提交草稿和未完成会话不作为学习证据。AI分析可综合所有提交事件，但必须区分 practice 与 scheduled；W5仅允许现有白名单调度动作，经用户确认后应用。

来源失效判断不得使用会因队列/草稿/暂停等无关操作变化的全局 protocol dataRevision。应使用分析数据域指纹，覆盖已提交学习事件、当前 FSRS、内容版本、调度策略、知识点关联和影响分析的配置。会话生命周期写入不改变该指纹。

## 7. 旧会话兼容
旧会话无法确定来源时一律按 practice 读取；保留原 sessionId、进度、草稿和逐卡已提交事件。不得补造 schedule_events、追溯运行 FSRS 或删除会话。旧历史事件保留原 practice 标记。

## 8. 概览 UI
卡片集概览页只显示一个正式复盘主入口：
- 有未完成正式队列：显示“继续正式复盘 · 已完成/总数”。
- 无活动队列且有到期卡：显示“开始正式复盘 · N张待复盘”。
- 无到期卡：显示“今日正式复盘已完成”，入口禁用或引导自主练习。
自主练习入口仍在卡片列表/筛选规划器，不显示成正式队列。
概览只展示正式队列状态；自主练习历史在历史页中查看。
开始/恢复/提交必须有 loading、成功、失败、重试反馈。

## 9. 关键一致性边界
- 卡片集正式队列唯一性是数据库领域约束，不依赖前端按钮禁用。
- practice 会话绝不阻挡 scheduled 创建，scheduled 会话也不锁卡片自主练习。
- 同一卡片不应存在两个正式队列；若历史异常数据存在，升级兼容时只保留一个正式活动会话，其余旧会话转为 practice，保留进度，不删除。
- 正式队列期间的卡片内容修改不影响调度，也不使旧会话草稿失效；事件记录其实际使用的旧版本。
- 仅卡片内容版本变化不应作为拒绝提交理由；cycleId变化仍需检查，因为它代表学习周期语义改变。
