# GankSoft v0.7.3 RC 实施与设计对照

本版以最新保存的 v0.7.2 RC 为基线，按用户指定 `02-Codex指令/01-直接复制给Codex的主指令.txt` 的 P0→P6 顺序增量实现。原设计保存在 `docs/v0.7.3-input/`，其中“未实现”字样是原需求状态；本文件和本版验证记录说明实际结果。

## P0：身份与保护

- 初始工作区仅有需求 ZIP，没有用户源码或 dirty 修改。恢复于独立 `project/GankSoft-v0.7.2-source`，未覆盖旧工作区。
- v0.7.2 整合包 SHA256 `cb061f72b191dd6db9d2849e6fdb6e7949361b7b6b29e98199a87ac2c2dae0bb`；内嵌源码 `da5d4caafeb5c502dd75092d0028f06468f03b956934fdfa98bfcd687bda66bc`，重新计算一致。
- 归档没有 Git 历史，建立本地基线提交后分阶段提交；没有声称恢复以前丢失的提交。
- 实际入口 App→useStudySession→review/workflow→review/service→review/fsrs。主要设置为 DeckReviewSettings、CardReviewPolicy、AssessmentPolicyEditor。旧 ReviewHub/ReviewWorkspace 不作为主实现。
- 原库 schema601，原间隔表、目标用时表、事务、回执与完整数据库备份可复用。原保持率固定0.90，旧自动队列使用最近三次失败，旧每日上限计事件，保存间隔并不调整当前计划。
- 高风险：到期覆盖、迁移/恢复、原子回执；中风险：诊断归因、预算和推荐；低风险：分区设置与提示。依次先测纯逻辑，再测数据库/协议，再测 Electron 与成品。

## P1：已实现

`effectiveReviewPolicy` 是有效间隔和来源的服务端解析器；来源 `card_override/deck_default`。单卡可大于集上限；null才清除覆盖。旧三个保存API保持兼容。新增 `policy.card.get`，单卡设置从后端读取有效值。

`shared/review-budget.ts` 计算独立卡数、重学事件和练习事件，正常队列在服务端按不同卡ID计预算，历史报表保留原口径。自动学习入口统一调用 `policy.previewQueue`。有新证据快照的已移动卡，不把旧集当天作答挪用为新集预算；无法还原所属集的旧历史仍按既有卡归属处理，不能捏造历史集快照。

## P2：已实现

schema602 增加 `deck_review_config_v2`、`knowledge_specialty_prefs`、`diagnosis_config`。配置经共享Zod和服务端校验，JSON列有有效性/关键边界CHECK，完整备份恢复再次校验全部字段。采用CAS revision、审计和协议幂等回执，保留原策略表。默认不写全体既有卡片集配置行，不改旧值。

支持集级保持率0.80—0.97（默认0.90）、重学/专项预算、时长软目标、四预设/自定义权重、严重逾期预留、多样性、跨题验证、疲劳和有种子的随机专项。知识偏好支持模式、boost、目标数、变式优先、暂停。全局高级诊断控制半衰期、单题贡献上限和重复衰减。

FSRS仅在下次有效复盘读取所属集保持率，并在新排期事件日志记录；不回算既有稳定性/难度/due。

## P3：已实现

schema603 增加 `review_due_overrides` 和 `review_config_operations`。

- `due-eligibility.ts` 唯一解析资格：暂停 > 显式延期 > 有效策略提前 > 原计划到期。原 `plans.due_at` 是兼容显示权威（包含旧tomorrow延期），缺计划才退回原始FSRS due；保留原始FSRS JSON。应用快照和 `schedulingDue` 调用同一服务。
- 旧 `content.plan.set` 公共协议仍只开放原权限，未为批量调整开放任意due SQL。内部旧tomorrow更改原plan并有显式原因，统一资格层识别为延期，批量提前跳过。
- 默认 `future_only` 不改当前任务。独立只读预览分页（默认50、最大100），统计继承/覆盖、立即到期和跳过原因。
- 服务签名令牌绑定集/卡、配置/数据指纹、学习时区、规则版本、计算时刻，5分钟过期；进程重启后需重新预览。配置、复盘、计划、卡移动/编辑或时钟回退使旧预览拒绝。
- 明确确认后才原子写覆盖、操作回执和审计；仅提前，公式 min(oldEffectiveDue,max(now,last_review+cap))；无可信last_review/首学、暂停、删除、显式延期默认跳过。单卡覆盖始终优先。
- 重复requestId返回原回执。未知回包复用现有operation.status机制核验，不自动换编号重提。
- 撤销仅移除尚未复盘或人工修改的本次覆盖；后续有效FSRS复盘清除覆盖。覆盖失效时保留原始历史，不盲恢复算法状态。
- 未接入的旧clampCurrentPlan仍是历史内部辅助函数，保存路径不调用；新版提前仅使用独立覆盖层。

## P4：已实现的纵向切片

schema604 增加 `attempt_evidence_snapshots`。新作答的关联知识ID、关联指纹、所属集、学习时区和练习模式与attempt、回执处于同一事务。旧历史不补造正面关联。

`shared/review-evidence.ts` 与 `review/diagnosis.ts`：当前内容版本的全部适用历史、双向时间衰减、同题同自然日首个独立事件、跨题/跨日可信度、每题贡献上限、重复衰减、明确错误归因、父子事件去重、证据不足/过时/改善/薄弱等状态和有滞后区间的阈值。指数是解释性证据量，不是掌握概率。记忆卡不进入解题知识诊断。历史图表范围不输入本诊断模型。

`review/review-queue.ts` 和 `shared/review-priority-v2.ts`：先合法资格，再分正常到期/同日重学/非到期专项池；严重逾期按最早到期保障，四权重、知识点分散、疲劳、变式偏好和seed可复现。每张卡在队列只出现一次。专项偏好不会改FSRS；排除专项不删正常到期。正常会话记录队列规则/配置/数据版本和seed以供恢复追溯。

显式工程适配：严重逾期至少服务一题（即便预留比例为0），避免加权排序饥饿；知识点专项使用统一候选池和原因码表达薄弱/纠偏/覆盖，复用原筛选学习入口，不新增一套学习引擎。时长为软目标，展示而不截断作答。新队列不缓存派生结果，按集按需读取并计算指纹，避免缓存失效漏项；诊断回传有分页。暂无变式组自动识别（原方案仅要求扩展位）。

## P5：已实现

现行集设置增加排期/每日任务/智能推荐/知识点专项分类；原集最大间隔和每日上限复用原保存API。原参数保存与新版参数保存有独立结果提示，提前是独立预览和确认操作。单卡显示有效值来源、继承/独立和下次生效说明。用时目标三态和记忆/错题区分保留。

`AdaptiveReviewSettings`、`ExistingPlanPreview`、`ReviewQueuePreview`、`DiagnosisSettings` 为小组件。离页/关窗保护未保存编辑、切换知识点确认、保存回包不覆盖期间新输入、请求代次防迟到覆盖。复用主题变量。额外专项明确 practice=true；学习结果页可查看独立诊断，答题揭示前不自动展示历史诊断影响独立作答。

## 数据与风险边界

数据空间仍为 `v060/data`。迁移链601→602→603→604，只添加新表。600库先升级601。完整备份包含整个SQLite和图片，接受旧600/601及新版602/603/604备份；内容交换ZIP仍只含内容。禁止用旧版打开升级后的库，应从升级前完整备份回退。
