## W8.2 — 后续独立授权的正式实现（未来）

建议不超过三个技术检查点：

1. W8.2-A：Electron 主进程持有 W4 导出 job，Vue 卸载不再隐式 cancel；全局唯一轻量任务只读状态、显式取消、完成通知；关闭应用安全取消并清理。**已存在 export.status 仅含 phase/cardCount/eventCount/bytes，无分母/百分比**：界面先显示真实数与阶段，不准伪百分比。保留固定只读快照、CRC/SHA/原子落盘；导出期间正式复盘致已完成 ZIP 过期时标记不能用于当前分析。
2. W8.2-B：原始 W4 ZIP 的主进程**受权文件引用+来源身份**最小索引、AI ZIP 先选一份后由其 source 精确定位原始 ZIP、失联一次补选。现有 W4 ExportResult 没有 exportId/绝对路径，必须在已验证 ZIP manifest 和保存授权环节取得身份，绝不由 renderer 伪造路径；保留 W5 原源包完整校验、revision/epoch/目标指纹、换库缓存隔离和隐私最小化。
3. W8.2-C：更新 src/unified/UnifiedAiAnalysis.vue 的界面结构，默认收起高级导出设置；导入默认合法建议选中，点击应用即自动 prepare，随后单次最终确认，执行/撤销和日志继续走 W5 原 API。**增加源 epoch/revision/目标指纹变化触发的工作区弹窗**：取消准备态、阻止旧建议写入，“暂不处理”保持 stale 锁定，“重新导出”产生新 W4 包并要求用户用外部 AI 重新生成返回 ZIP；服务端最终 CAS 仍必须复验。

实现前读取真实 HEAD、AGENTS、STANDARDS，确认 API、schema 和 W5 的使用位置；必要时只增最小共享协议，不创建第二套任务/调度数据库。不要把自动补选设计扩展成跨任意路径读取。
